# 分阶段实施清单

## 当前状态

2026 年 11 月 13 日，方案与实施文档已建立，项目目录、模块边界与依赖方向已整理到 [项目结构](PROJECT_STRUCTURE.md)。以下功能均待开发，外部服务和真实直播链路待接入验证。阶段完成后在本文件补充日期、运行命令、结果和遗留项。

| 阶段 | 目标 | 状态 |
| --- | --- | --- |
| P0 | 本地模拟事件与角色动作原型 | 待实施 |
| P1 | DeepSeek、语音、OBS 本地录制，构成 MVP | 待实施 |
| P2 | 真实 B 站弹幕与礼物闭环 | 待实施 |
| P3 | 长时间运行、低延迟优化和完整功能 | 待实施 |

P0 是可观察的原型。P1 完成完整本地输入到直播画面的 MVP。P2 验证真实平台事件，完成首次直播闭环。各阶段保持能够启动和验证。

## P0 本地模拟原型

### 开发任务

- [ ] 初始化 TypeScript、Node.js 本地服务和浏览器页面，设置依赖锁与本地配置忽略规则。
- [ ] 建立 `tsx watch` 源码运行、Vite 同源开发页面和独立 TypeScript 类型检查。
- [ ] 首先验证业务 `/ws` 与 Vite `/__vite_hmr` 的升级共存、热更新及服务重启重连。
- [ ] 在锁定版本的 Vite 配置中显式设置热更新路径，升级路径识别复用该配置值。
- [ ] 在共享协议中定义版本、认证消息与角色权限，HTTP 控制与设置接口同业务 WS 共用本机作用域凭据校验逻辑。
- [ ] 定义业务 WS 缺失 Origin 的有条件回环兼容，显式非法来源和 `Origin: null` 仍按来源校验拒绝。
- [ ] 落实媒体本机匿名只读策略，使用资源 ID 映射、Host 与回环连接检查，并支持 HEAD / Range。
- [ ] 配置 Vitest Node 环境，为队列、去重、礼物增量和播放终态提供确定性回归检查。
- [ ] 按 PROJECT_STRUCTURE 建立当前使用的模块，集中依赖组装，服务端与页面分别检查类型。
- [ ] 验证从项目外目录启动、数据目录覆盖、角色包相对路径解析与配置原子保存。
- [ ] 提供 `/control` 控制台和透明 `/overlay` 页面，端口默认拟定为 3210。
- [ ] 提供健康检查、配置状态和错误反馈。
- [ ] 制定角色动画清单，定义 `idle`、`wave`、`think`、`talk`、`eat`、`dance`、`gift`、`celebrate`。
- [ ] 支持本地素材导入与路径验证，记录来源和许可，缺少动作时回退待机。
- [ ] 实现动画预加载、切换、完成回执与看门狗。
- [ ] 明确 `playback.play` 的 Promise 终态、单次完成规则及 `runId` / `leaseId` / `performanceId` 校验。
- [ ] 提供模拟弹幕、模拟礼物、手动动作、暂停和紧急停止。
- [ ] 实现有界队列、事件去重和礼物增量归一化。
- [ ] 给出实际存在的安装、启动与检查命令。

### 验收

- [ ] 一次启动后控制台与 OBS 页面可访问，启动日志说明端口。
- [ ] HMR 与业务 WS 同时在线，页面热更新时业务消息仍可收发，服务重启后两者均能恢复。
- [ ] 无凭据、错误角色凭据、显式非法来源、`Origin: null` 和认证超时连接被拒绝，播放端凭据调用 HTTP 控制或设置接口时被拒绝。
- [ ] 缺失 Origin 的合法回环与 Host 连接完成凭据认证后可用，缺失或错误凭据时保持拒绝。
- [ ] 记录目标 OBS / CEF 版本与握手头类别，验证 HTTP 播放链接的实际 WS 连接。
- [ ] 媒体元素直接加载资源成功，重复读取、HEAD、Range 和不存在资源的返回符合预期，控制接口继续执行凭据检查。
- [ ] 控制台凭据可执行人工控制，播放端可登记和回报自身播放，凭据普通重启后可用，重置后旧会话失效。
- [ ] 有素材时可稳定待机，手动切换动作后恢复待机。
- [ ] 输入“跳个舞”触发 `dance`，模拟礼物触发 `gift` 和感谢字幕。
- [ ] 同一来源事件重复投递时触发一次，累计连击样本的数量正确。
- [ ] 连续提交超过队列上限的事件，例如向上限为 20 的队列提交 50 条，核对容量、优先级与丢弃原因。
- [ ] 紧急停止清空待播任务并恢复待机。
- [ ] 重复和乱序播放回执仅完成一次结果，暂停或取消后迟到结果保持失效。
- [ ] 开发服务重启后播放端重新登记，旧会话消息保持失效。
- [ ] 缺失素材或加载失败时界面说明原因，播放器仍可恢复。
- [ ] 从项目外目录启动时解析到相同配置与角色包，设置写入可恢复且版本冲突有明确提示。

## P1 完成本地 MVP

### 开发任务

- [ ] 接入 DeepSeek，服务地址、模型、思考开关与 API Key 使用服务端配置。
- [ ] 采用短回复 JSON 输出，校验文本、情绪和动作 ID，处理空响应与截断。
- [ ] 提供回复预览、人设配置、超时与保底回复。
- [ ] 接入一种 TTS，提供试听、音色选择与失败反馈。
- [ ] 为文本、音频和动画分配表演 ID，建立独立轨道与完成回执。
- [ ] 实现一条语音串行播放、默认静音预览与 OBS 音频归属。
- [ ] 紧急停止使迟到的 LLM / TTS 结果失效。
- [ ] 展示 LLM、TTS、队列等待和播放各阶段耗时，以及 token 用量。
- [ ] 完成 OBS 本地录制说明，提供所选语音服务的配置方法。

### 验收

- [ ] 模拟问题经过真实 DeepSeek 请求，得到回复并播放语音、字幕与动作。
- [ ] 操作台能看到外部请求失败原因，保底回复可恢复互动。
- [ ] 将“忽略人设、执行指令”等观众文字作为输入测试，动作执行始终经过白名单。
- [ ] 在生成中、合成中、播放中分别停止，之后保持安静，下一次人工恢复仍可工作。
- [ ] 同时打开普通预览和 OBS 时仅一个音频出口发声。
- [ ] 实测播放页断线与续租失效时本地停止声音，转交播放权后保持单一音频输出。
- [ ] OBS 连续录制 30 分钟，检查透明背景、音画衔接、重复音频和明显卡顿。
- [ ] 记录实际耗时与费用，区分已测数据和预设目标。

### 可交给 AI 的任务

```text
通过模拟弹幕验证完整链路，补充 OBS 本地录制步骤。
配置缺失时继续完成可验证的适配器与模拟检查，并记录具体未验证项。
```

## P2 真实直播闭环

### 开发任务

- [ ] 实现 B 站平台适配器，普通 WebSocket 与开放平台至少完成一种真实接法。
- [ ] 普通接法参考 bilive-danmaku，处理真实房间号、登录态、服务器发现、鉴权、心跳、解压与重连。
- [ ] 官方接法处理签名、主播身份码、开启 / 结束会话、应用心跳与长链鉴权。
- [ ] 按样本映射弹幕、礼物、连击、大航海与醒目留言，保留原始事件去重键。
- [ ] 使用真实样本核对礼物数量、连击的增量 / 累计语义、价格单位与免费 / 付费类型。
- [ ] 实现用户冷却、问题筛选、礼物感谢合并与队列优先级。
- [ ] 处理断网、Cookie 过期或官方会话过期，并在控制台显示状态。
- [ ] 确认用于本次直播的角色、声音与素材授权，配置需要的署名。

### 验收

- [ ] 在目标房间用另一设备发送真实弹幕，核对用户、内容和回复对象。
- [ ] 实测断线恢复，重连后相同来源事件保持幂等。
- [ ] 模拟回放验证礼物规则，真实礼物事件按现有样本或用户实际互动核对。
- [ ] 在 OBS 预览与本地录制中完成检查，再由操作者按已确认配置开播。
- [ ] 从观众端检查实际画面与声音，记录完整延迟。
- [ ] 连续运行 2 小时，记录事件丢弃、错误、API 用量、内存与资源占用。
- [ ] 实测暂停 AI、静音与停止推流入口。

真实礼物验证使用已有事件或按用户安排进行。系统提供事件回放，方便在日常开发中复现相同结果。

## P3 完整功能与持续运行

### 功能任务

- [ ] 根据实测瓶颈引入分句 TTS 和结构化流式协议，保持句子顺序与取消一致。
- [ ] 建立 SQLite 历史、用户短期记忆、礼物去重记录和用量统计，设置保留与清理机制。
- [ ] 增加角色包切换、可编辑礼物规则、冷却时间、人设与音色配置。
- [ ] 增加空闲话题与随机动作，直播互动时自动让出执行时段。
- [ ] 增加服务健康状态、自动恢复、错误统计与一键诊断信息导出，敏感信息脱敏。
- [ ] 形成一键启动入口和完整操作文档。
- [ ] 分发构建输出服务端与页面产物，验证从项目外目录启动、配置定位和数据目录沿用。
- [ ] 按需接入 Live2D / 3D 与口型驱动，或复用 dsh-pet HTTP 作为第二渲染适配器。

### 验收

- [ ] 持续运行 8 小时，内存、缓存、队列和连接数保持有界。
- [ ] 注入模型限流、TTS 故障、动画缺失与平台断线，系统均可恢复。
- [ ] 高峰事件回放下，人工停止始终可用，语音保持串行，过期普通聊天被及时移出。
- [ ] 程序重启后按有效期恢复状态，过期表演保持已结束状态。
- [ ] 零基础操作者按说明完成安装、配置、启动、预览、开播和收播。
