# 零基础准备与操作指南

P0 已于 2026 年 11 月 13 日交付：本地服务、控制台与透明播放页可用，支持模拟弹幕 / 礼物、手动动作、暂停与紧急停止。DeepSeek、语音与真实直播在 P1 / P2 交付。安装与启动见第 3 节的实测命令。

## 1. 准备清单

| 项目 | 用途 | 何时需要 |
| --- | --- | --- |
| Windows 电脑与稳定网络 | 跑本地服务、动画与 OBS | 开始前 |
| OBS Studio | 把画面与声音编码并推到直播平台 | P1 |
| Node.js 受支持的 LTS | 运行 WhaleTalk 本地服务 | P0 |
| DeepSeek API Key | 根据弹幕生成回复 | P1 |
| 语音合成方案 | 将回复变成声音 | P1 |
| 角色动作素材 | 展示人物与动作 | P0 |
| B 站直播账号与房间信息 | 真实弹幕接入和推流 | P2 |
| 开放平台凭据，选择官方接法时 | 正式事件通道 | P2 |

DeepSeek 网页聊天账号与 API 调用分别配置。API Key 在 DeepSeek 开放平台创建，使用量按平台计费。将密钥填入实现后的本地配置文件，保存于自己的电脑。[DeepSeek 平台](https://platform.deepseek.com/)

## 2. 先看现成大肥鱼

这是可立即尝试的桌宠体验路线。

1. 打开 dsh-pet 的 Releases，找到 Windows x64 绿色包 `dsh-pet-win-x64.zip`。
2. 解压，运行其中的 `dsh-pet.exe`。
3. 查看待机和右键动作，确认电脑可以正常播放动画。
4. 查看运行日志中的实际本地服务端口。

该绿色版按仓库说明包含 Electron，无需另外安装 Node.js 或 DSH。独立模式的 AI 对话依赖后续外接服务。[下载页面](https://github.com/PC2005-cloud/dsh-pet/releases) [独立模式说明](https://github.com/PC2005-cloud/dsh-pet/blob/main/INSTALL.md)

已有 Node.js 且满足 dsh-pet 当前最低版本要求 22.12.0 时，可以使用仓库提供的命令。

```powershell
npm install -g dsh-pet
dsh-pet-standalone --check
dsh-pet-standalone --port 3080
```

默认独立模式地址为 `http://127.0.0.1:3080`。访问根路径可读取服务信息。角色显示于独立桌面窗口，OBS 捕获窗口的透明效果需要实际测试。[安装说明](https://github.com/PC2005-cloud/dsh-pet/blob/main/INSTALL.md)

## 3. WhaleTalk 的安装与启动（P0 实测命令）

在项目根目录用终端依次执行（Node.js 需 22.12 或更高，本机以 24.12 验证）：

```powershell
npm install          # 安装依赖并生成锁定文件
npm start            # 普通启动（持续录制/直播用）
```

启动后按 `Ctrl+C` 停止。启动输出会给出两个**含凭据**的地址：`/control#…` 是控制台，`/overlay#…` 是给 OBS 的播放页链接，请勿外传。端口默认 3210，可用 `npm start -- --port 3311` 覆盖。

其他命令：

```powershell
npm run dev                # 开发模式:改服务端源码自动重启(会重置内存队列)
npm run check              # 类型检查(服务端+页面)与全部回归测试
npm run test               # 仅回归测试
node scripts/ws-smoke.mjs  # 全链路冒烟自检(需服务已启动)
npm run gen:test-assets    # 生成占位角色素材(需带 libvpx 的 ffmpeg,可用 FFMPEG_PATH 指定)
npm run start:reset-access # 重置本机访问凭据(旧链接全部失效,需重新复制)
```

环境配置保存在项目根的 `.env.local`（参考 `.env.example` 复制创建）。当前已生效的键与 P1/P2 依赖如下：

```dotenv
HOST=127.0.0.1
PORT=3210
PLATFORM=mock

DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_THINKING=disabled

TTS_PROVIDER=edge
WHALETALK_DATA_DIR=./data
PET_ID=main

BILIBILI_ROOM_ID=
BILIBILI_COOKIE=
BILIBILI_OPEN_ACCESS_KEY_ID=
BILIBILI_OPEN_ACCESS_KEY_SECRET=
BILIBILI_OPEN_APP_ID=
BILIBILI_OPEN_CODE=
```

初始 `PLATFORM=mock` 使用模拟事件。`bilibili-web` 接法按实现和当前平台要求配置房间号及登录信息，`bilibili-open` 接法配置应用凭据和主播身份码（键名 `BILIBILI_OPEN_CODE`）。TTS 音色列表由所选提供方加载，正式云语音服务增加其对应配置。

### 3.0 语音（已默认配置，无需额外步骤）

语音默认使用 **edge-tts**（微软 Edge 朗读通道，免费），安装后开箱即用：发弹幕角色即用真人声回应。音色可在控制台设置面板的「语音区块」下拉选择并**试听**后保存（默认 `zh-CN-XiaoxiaoNeural` 晓晓女声）。

### 3.1 接入 DeepSeek（P1 第三批）

回复默认使用离线固定回复，零配置即可启动。接入真实模型只需两步：

1. 在 `.env.local` 填写 `DEEPSEEK_API_KEY`（在 DeepSeek 开放平台创建，按用量计费）。按需调整 `DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`、`DEEPSEEK_THINKING`（`enabled` 开启思考）。这些值只在服务端读取，不会出现在控制台或浏览器。
2. 重启服务。控制台设置面板的「回复来源」选择 `deepseek`；「配置状态」显示密钥已配置、当前生效为 DeepSeek 即成功。填好密钥后路由自动切换，无需改其它设置。

> **使用本地自部署模型**（vLLM 等内网/隧道部署）：不需要改代码，同样只改 `.env.local` 的 `DEEPSEEK_BASE_URL`/`DEEPSEEK_MODEL`。连接与排障步骤见本地文档 `docs/MODEL_SERVICE_ACCESS.md`（含服务器拓扑，该文件**已加入 .gitignore 不入库**，仅本地保留）。

密钥未填或模型调用失败时，回复自动降级为固定文本并在控制台标注来源 `fallback`，直播不会中断。可用设置面板的「回复预览」输入一句话，核对回复文本、动作、来源、耗时与 token 用量；队列区的「耗时与用量」展示排队、生成、合成、播放各阶段耗时与累计 token。模型输出只接受白名单动作，观众弹幕里的指令文字不会被执行。

环境配置保存在项目根的 `.env.local`（可先复制 `.env.example`）。`WHALETALK_DATA_DIR` 指定用户数据目录，示例中的 `main` 角色包位于 `data/pets/main/manifest.json`。界面修改的设置保存在 `data/config`，动画、日志和语音缓存分别保存在数据目录的对应子目录。备份时保留用户配置、角色包和后续数据库，本地密钥单独妥善保存。详细路径见 [项目结构](PROJECT_STRUCTURE.md)。

服务启动后，使用启动输出的 `http://127.0.0.1:3210/control#<凭据>` 操作角色，把 `http://127.0.0.1:3210/overlay#<凭据>` 提供给 OBS。端口可修改，实际地址以启动输出为准。

实际操作使用启动入口给出的控制台访问链接，并从控制台复制 OBS 播放链接。应用自动生成并保存相应用途的本机凭据，普通重启沿用，显式重置后重新复制链接。`data/access.json` 按本地密钥妥善保存。

开发时使用源码监视模式，改动服务端源码会重启服务并重置内存任务。持续录制和直播使用实现后提供的普通启动入口。页面断开后会停止当前音频，重连后重新取得播放权限。源码运行和分发构建的区别见 [开发工具约定](PROJECT_STRUCTURE.md)。

## 4. 把透明画面加入 OBS

以下步骤用于 WhaleTalk 的浏览器画面路线，需先完成 P0 / P1。

1. 安装并打开 OBS，新建一个场景。
2. 在“来源”中添加背景图片、颜色或自己的直播场景（**必须有非黑色背景**，否则空场景本身是黑色，无法区分透明是否生效）。
3. 添加“浏览器”来源，名称可以填写“WhaleTalk 角色”。
4. URL 填入应用给出的 `/overlay` 链接（控制台“OBS 播放页链接”复制的那条，**含 `?audio=1` 与 `#` 后凭据**，完整粘贴）。`?audio=1` 表示申请音频播放权；直接打开不带参数的 `/overlay` 是静音预览，不会抢走 OBS 的声音。
5. 首次可设置为 1280 × 720、30 FPS，并让 OBS 画布与输出分辨率一致。
6. 将角色来源放到背景上方，检查透明区域、人物尺寸、字幕与屏幕边缘。
7. 首次联调时关闭“不可见时关闭源”和“场景变为活动状态时刷新浏览器”。切场景后观察页面连接和播放状态。

OBS 浏览器源支持网页画面、透明背景与音频。**实测（OBS 33.0.1，2026-11-18）**：OBS 内置浏览器（CEF）原生解码 VP9-alpha 透明素材，直接使用播放页链接即可透明；曾出现的“黑底”实为**空场景本身的黑色**（OBS 空场景默认渲染为黑，并非素材或页面问题），为场景添加任意非黑色背景即可辨别与避免。早期试验的 `?blend=screen` 混合模式兜底经像素级验证无法在网页内去除不透明黑底，已移除，不要使用。[OBS 浏览器源说明](https://obsproject.com/kb/browser-source)

## 5. 让声音只出现一次

1. 在浏览器来源属性中启用“通过 OBS 控制音频”，具体名称随版本语言可能略有差异。
2. 从 WhaleTalk 发起语音试听，在 OBS 混音器确认角色来源的音量条变化。
3. 普通浏览器预览保持静音，指定 OBS 页面为音频播放端。
4. 首次把角色音频监听设为“关闭监听”，录制 30 秒并回放，确认输出含声音。
5. 需要自己监听时选择对应监听设备，再检查桌面音频是否同时采集该设备，调整到单一路径。

若音量条有变化而录制无声音，检查音轨分配、静音、来源属性与输出设置。若声音重叠，检查预览页面、重复浏览器源和桌面音频采集路径。

## 6. 接入 B 站弹幕

### 普通接法

在控制台选择普通 B 站连接，填房间号。若界面提示登录信息缺失或过期，按适配器的登录说明处理，并在本机保存。用第二设备发一条“你好”，先检查事件面板，再检查回复和动作。bilive-danmaku 的 README 提醒，未登录可能无法取得完整弹幕数据。[弹幕项目说明](https://github.com/Beats0/bilive-danmaku)

### 官方接法

按开放平台当前接入说明申请开发者与项目，获得应用凭据，再由主播提供身份码。控制台应显示互动会话、长链和心跳状态。只填房间号无法完成官方应用鉴权。[开放平台](https://open-live.bilibili.com/) [官方接入示例](https://github.com/bilibili-openplatform/OpenLive_CSharpDemo)

两种方式各自核对实际连接要求，相关凭据放在本地服务配置中。

## 7. 从测试到开播

1. 先用模拟事件验证吃饭、跳舞、感谢、说话和紧急停止。
2. 配好 DeepSeek 和 TTS，完成一次完整回复，再断开外部服务验证错误提示。
3. OBS 本地录制 30 分钟，回放检查画面、字幕、声音和切换。
4. 接入目标房间，用另一设备发真实弹幕，核对回复对象。
5. 确认当前账号的直播权限、角色与声音授权，以及平台页面显示的 AI / 虚拟形象要求。
6. 从 B 站直播中心取得推流配置，填入 OBS，先采用平台建议的编码参数。
7. 开播后从观众设备检查成片，分别记录发弹幕、角色回应与观众看到回应的时间。
8. 收播时停止推流，再停止平台互动会话和本地程序。

推流密钥同样属于本地敏感配置。开播与收礼用途采用覆盖相应用途的角色授权。[素材许可](https://github.com/PC2005-cloud/dsh-pet#许可)

### 7.1 点歌唱歌（P3）

观众发弹幕「点歌 歌名 歌手」即可触发（首次约 2 分钟后台准备，二次点同一首秒出；角色清唱副歌片段，音色与说话一致）。该功能依赖三个**本地工具链**，缺一不可：

1. **RVC 运行时与音色模型**（`.tools/rvc/RVC20260718DML/`）：官方 RVC 完整包（含自带 `runtime/python.exe` 与 `ffmpeg.exe`），解压到该路径；音色模型 `tidepost.pth` 放入其 `assets/weights/`，faiss 索引 `added_*tidepost_v2.index` 放入其 `logs/tidepost/`。
2. **Demucs 分离环境**（`.tools/conda/whaletalk-song/`）：conda 环境（Python ≥3.10 + torch CPU + demucs），用于人声/伴奏分离；模型缓存写在 `.tools/torch-home/`（自动生成）。
3. **容量与权限**：`.tools/` 与 `data/` 所在磁盘预留 ≥2GB；**不要把数据目录放在系统临时目录**（RVC 运行时写 %TEMP% 会被杀软拦截）。

验证安装是否完整（全绿即可用）：

```
node scripts/singing-smoke.mjs 3721
```

冒烟会启动隔离实例并发起两次真实点歌（B 站搜歌→分离→换声→落盘，另有一次「查无此歌」的失败路径），约 2-3 分钟；18 项全部通过说明管线与控制台点歌面板的数据源都正常。缺依赖时的提示：`spawn` 报 `ENOENT` 对应路径不存在；`PYTHONIOENCODING` 乱码说明用了非官方 runtime；日志出现 `search: no reliable match` 说明该歌没有可靠源（换歌名重试）。

**查看点歌进度**：控制台的「点歌任务」区块列出最近任务——阶段（排队中 → 搜歌下载 → 人声分离 → 音高分析 → 换声中 → 已就绪）、来源视频标题、移调值与耗时。「已就绪」的任务带试听播放器（成片已同时排入待播队列）；失败任务显示中文原因（如「取歌失败:…」），鼠标悬停可看完整报错。「在途 n / 2」是正在制作的任务数，占满时新点歌会被婉拒。点歌后没动静时先看这里。

面板本身的浏览器实测（需要本机 Edge，用预置成片缓存，不跑完整管线）：

```
node scripts/singing-panel-e2e.mjs 3793
```

想知道点歌慢在哪一步，可单独跑一遍分步计时（约 2–3 分钟，依次报告搜歌、分离、音高分析、换声、编码各用多少秒）：

```
node scripts/song/pipeline-timing-probe.mjs "篇章 张韶涵 MV"
```

电脑开机后第一次运行得到的是「冷启动」耗时，紧接着再运行一次是「热启动」耗时。

两点自动行为，无需配置：服务启动时会在后台预热一次换声运行时（日志 `singing.warmup … warmup finished`，约半分钟，只此一次）；每首歌的换声进程与搜歌并行启动，首次点歌比早期版本快约 20 秒。预热失败（工具链缺失等）只记日志，不影响点歌与播出。

## 8. 常见问题

| 现象 | 排查顺序 |
| --- | --- |
| OBS 页面打不开 | 本地程序是否启动、端口是否一致、地址是否可在浏览器访问 |
| 人物黑底 | 场景是否有非黑色背景（OBS 空场景默认渲染为黑，先用颜色源验证透明）；素材源文件是否带 alpha；播放页链接是否完整含 `#` 后凭据 |
| 切动作闪黑 | 新动作是否预加载、首帧是否可用、双缓冲切换是否成功 |
| 角色有文字却没声音 | TTS 状态、音频加载结果、播放端归属、OBS 静音与音轨 |
| 同一句读两次 | 重复 OBS 来源、浏览器预览、桌面音频、来源事件去重 |
| 弹幕收不到 | 房间号、登录态或应用授权、长链鉴权、心跳和错误面板 |
| 回复越来越迟 | 队列等待、语音长度、调用耗时、用户冷却和过期任务清理 |
| 停止后又开口 | 在途请求的取消标识、迟到结果丢弃、旧页面播放归属 |
| 礼物数量偏大 | 增量与累计字段、连击统计通知是否双算、来源去重键 |
