## WT-P1-009 · P1 · 指定端口上的同名入口仍可被误停

重连脚本现在按端口查询监听进程，再检查进程名和命令行。代码中的命令行匹配实际只校验通用 `server/main.ts` 后缀，缺少 WhaleTalk 的工作区或测试进程归属判断。以同一请求端口的两个合成进程记录复核时，另一个项目的 `D:/OtherProject/src/server/main.ts` 可通过筛选。与之相邻的正则字符串转义也未保留预期字符，实际传给 PowerShell 的条件为 `server[/]main.ts`，常规 Windows 反斜杠入口路径反而匹配失败。两个重连脚本使用相同条件。[诊断脚本](../../../scripts/e2e-reconnect-trace.mjs#L52) · [重连脚本](../../../scripts/e2e-reconnect-idle.mjs#L137)

继续限定到由测试启动的 PID，或在停服务前核对明确的项目入口、端口与进程归属。回归应覆盖相同端口上的同名异项目入口和实际 Windows 路径。复审以合成记录验证筛选逻辑，实际验证过程中只关闭了自建测试服务。

## WT-P1-010 · P2 · 旧探测会刷新已恢复的播放页

探测文档时使用 `await fetch()`，独立的 WebSocket 重连仍在继续。允许四次连接尝试中的前三次触发受控超时，暂缓第三次触发的 HTTP 探测。第四次连接成功后，当前页面探针已为 `connected`，再完成旧探测并返回 200。实际 `createWsClient` 仍调用了一次 `location.reload()`。`open` 将计数归零，但 fetch 完成后没有核对该探测是否仍属于当前连接状态，已恢复的播放可能被无谓刷新。[探测与重载](../../../src/web/shared/ws-client.ts#L59) · [连接恢复](../../../src/web/shared/ws-client.ts#L151)

文档探测的异步结果应与连接代数及退出状态绑定，一旦连接恢复便取消或忽略旧探测。复测保留 503 后继续重试的场景，并加入探测悬置期间先重连成功的交错。独立时序验证执行的是实际模块和可控 WebSocket，对 503 的真实浏览器验证沿用修复记录。

## WT-P1-011 · P2 · 分块脱敏可留下完整凭据

两个脚本对每次子进程 `stdout`、`stderr` 的 `data` 块分别做整凭据替换。流块可以在任意位置分割。执行实际脱敏函数，用 32 字符合成凭据测试时，完整单块会被替换。将同一行在凭据中间拆成两块，分别脱敏后按脚本方式拼接，完整值仍然保留。脚本另外从固定的 `data/access.json` 读取替换条件，子进程使用自定义数据目录时，两者也可能不一致。[轨迹脚本的逐块处理](../../../scripts/e2e-reconnect-trace.mjs#L91) · [503 脚本的逐块处理](../../../scripts/e2e-selfheal-503.mjs#L52)

日志过滤应对完整行或可跨块匹配的缓冲执行。可直接过滤带凭据的启动链接，避免依赖调用方猜测数据目录。复测用合成凭据覆盖跨块、尾部无换行和替换数据目录的输出。

## WT-P1-012 · P2 · 候补端忽略租约提前释放，后续表演丢失语音

候补页根据拒绝消息中的 `retryAfterMs + 250` 设定独立计时器。服务端提前释放后会推送状态，播放页的 `state` 分支没有更新候补重试计划。用真实 Edge 双页及 10000 毫秒租约复测。B 先收到约 9518 毫秒等待建议，随后 A 本地停声并成功释放。服务端已无持有者，立即提交一条新弹幕。约 3.2 秒后 B 收到下一项，但服务端仍没有租约，本次派发已剥离 `audioUrl`。协议回归中手动重发的客户端能立即接管，页面自动重试仍错过了这次机会。[重试计时器](../../../src/web/overlay/main.ts#L107) · [播放页状态处理](../../../src/web/overlay/main.ts#L220) · [有声派发宽限](../../../src/server/modules/playback/index.ts#L102)

播放器应在服务器允许提前接管时重新评估等待，仍由服务端拒绝尚未安全的申请。验收从先开候补页、已收到有效期较长的拒绝开始，然后令主播放端先停声并关页，验证候补接管和紧随的有声互动。长等待用于确保安全的断线情况应保持受控。
