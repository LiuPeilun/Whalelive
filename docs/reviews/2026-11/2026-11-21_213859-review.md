# P2 互动玩法第一批修复复审

WT-P2-001 关闭。WT-P2-002、003 部分修复，仍有两项 P2 待处理。正常弹幕的答谢动作限制、缺素材拒绝和原复现提问都取得了直接的接口或派发证据。[上轮报告](2026-11-21_211705-review.md) · [修复记录](2026-11-21_211705-fixes.md)

## WT-P2-001 · 已关闭 · 直播答谢专属动作

本地假模型的普通弹幕请求提示中无 `stamp-letter`。假模型有意返回该动作后，调度记录 `reserved-gift`，最终派发 `talk` 并保留原回复。控制台的授权手动请求 `stamp-letter` 仍返回 HTTP 200 并派发该动作。可用的普通动作 `talk-nod` 也仍能被模型选中和派发。最高档答谢的真实礼物规则仍属后续批次。[候选过滤](../../../src/server/integrations/llm/deepseek.ts#L98) · [直播采纳](../../../src/server/modules/interaction/index.ts#L363)

## WT-P2-002 · P2 · 回复预览仍会显示播放时被拒绝的动作

上轮的两条服务端播放路径已修复。隔离副本缺失 `spin.webm` 时，普通弹幕在模型返回 `spin` 后保留文本并派发 `talk`。手动试播返回 HTTP 400、`ASSET_MISSING`，当前任务为空。[直播采纳](../../../src/server/modules/interaction/index.ts#L363) · [试播拒绝](../../../src/server/transport/http/index.ts#L252)

控制台的回复预览从 `generateStrict` 直接返回适配器结果，绕过互动层的候选校验。适配器仍只检查角色清单是否登记。用同一隔离实例和同一假模型分别返回 `spin`、`idle`、`stamp-letter` 时，三个动作都不在提示候选中，`POST /api/llm/preview` 仍返回 HTTP 200 和对应动作。页面把它显示在「动作」字段，操作者会看到直播实际不会采纳的选择。[适配器结果](../../../src/server/integrations/llm/deepseek.ts#L157) · [预览接口](../../../src/server/transport/http/index.ts#L231) · [预览显示](../../../src/web/control/features/settings-panel.ts#L96)

复审仍要求预览以实际允许的动作集合校验输出，边界外保留回复文本并将动作置空。现有试播下拉框仍把 `available=false` 选项作为可选项追加，上一轮的界面验收项「过滤或禁用缺素材动作」也待落实。服务端拒绝已通过，当前本机 19 段素材齐备。[试播下拉框](../../../src/web/control/features/manual-action.ts#L24)

## WT-P2-003 · P2 · 含彩蛋词的普通提问仍会命中其他旧动作

原复现「为什么要喝口茶？」已经进入问答，假模型请求增加一次并派发 `talk`。「敬个礼」「喝口茶」和明确旧指令「来跳个舞」分别成功派发 `salute`、`sip-tea`、`dance`，均跳过模型。

第一批约定含彩蛋词的普通问题走问答。实测「吃饭前喝口茶对肠胃有影响吗？」仍因包含「吃饭」派发 `eat`，固定回复为「干饭时间到,今天吃火锅!」，模型请求数增量为 0。修复删掉「为什么」后，其他旧包含模式仍能在同一类问题上覆盖问答。[旧动作匹配](../../../src/server/modules/interaction/rules.ts#L26) · [第一批范围](../../ROADMAP.md#L172)

复审验收应覆盖两个独立彩蛋口令、明确旧动作指令和含旧动作词的正常提问。保留上述两条问题作为复验样本。
