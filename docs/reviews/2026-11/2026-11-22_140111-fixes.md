## WT-P2-013 · P2 · 冷场已开始后仍可能被观众互动打断 — 已修复

- **"已开口"判定移入播放模块**:`trackStarted(performanceId, track)` 替换为 **`opened(performanceId)`**(`session.ts`)——依据**实际派发的轨道**判断:音频轨道存在时按音频回执,无声降级(派发时剥离 audioUrl)时按动画回执;`started` 与 `ended` 都算"开过口"(**保留开始事实直到该表演结算**),未开始/`failed` 不算;非当前表演一律 false。两条反例逐一修复:
  1. **音频 started→ended、动画仍在播**:`ended` 保留开过口的事实,查询恒为 true——冷场不再被打断;
  2. **无租约降为无声**:降级保留原表演 id(`playback/index.ts` 的 silent 派发),音频轨道为 null → 回落动画边界;互动层不再依赖派发前记录的 `hasAudio`(已随本修复移除——它在降级场景是过时信息),`CurrentTask` 与创建/更新处一并清理。
- **播放模块接口**:`PlaybackModule` 以 `opened(performanceId)` 替换 `trackStarted`;四个测试替身同步。
- **回归用例修正**(按审核要求):删除"播放 Promise 挂起=已开口"的错误假设,冷场取消边界测试改用**挂起式播放替身**——play 只经 abort(以 cancelled 兑现)或测试显式 finisher(以 ended 兑现)完成;断言前先确认冷场**仍在途**(`current.performanceId` 匹配),用 `outcomes` 记录兑现方式区分真正的取消与自然完成。两条用例:未开口 → `cancelled` + 互动立即派发;已开口 → 冷场自然 `ended` 后互动才派发。
- **真模块反例回归**(`playback/index.test.ts` 新增 2 例,使用真实 session 与模拟回执):反例 1(动画 started→音频 started→音频 ended,动画仍在播)全程 `opened=true`,结算后回 false;反例 2(登记播放端但不领租约,越过宽限期实际派发为无声)——动画未 started 时 `opened=false`、动画 started 后 `opened=true`。
