## WT-P1-009 · 启动登记与就绪检查缺口

**修复一:启动互斥锁(`scripts/lib/test-server.mjs`)**

陈旧登记的「读 PID → 校验 → 删除 → 重新占用」不是原子的——删除与重新占用之间可被并发启动器插占,复审实测双方都创建了服务子进程。现将**整个启动临界区**(陈旧回收 → wx 独占登记 → 日志打开 → spawn → 写 PID)放进同一把跨进程锁(`.tools/e2e-server-start.lock`,wx 创建,持锁期间完成全部步骤后释放)串行化:

- 锁内读出的陈旧登记不可能已被换主,回收安全;并发启动器排队进入,后者必然看到前者写入的活跃登记而拒绝;
- 锁陈旧兜底:持有者崩溃残留时按 mtime 超时(60s)视为陈旧可抢;获取超时(30s)显式报错。

**修复二:失败全路径释放登记**

`startTestServer` 的占用后步骤(日志打开/spawn/写 PID)全部纳入 try-catch:任一步失败时删除本次占用的登记文件并关闭日志句柄再抛出——目录阻塞日志路径等失败不再遗留空登记卡死后续启动(「启动进行中」误报)。`startTestServer` 因锁等待变为 async,四个调用方已适配 `await`。

**修复三:监听者按健康 URL 同地址核对 + 超时收尾**

- `listenerPidFor` 增加 `-LocalAddress 127.0.0.1` 过滤:与健康请求同一地址——`::1` 上的其他监听者不再被误取导致就绪误判(IPv6 替身监听同端口时,127.0.0.1 上本子进程的监听照常命中);
- CLI 就绪超时路径收尾:`child.kill()` 终止本次子进程(登记由子进程退出回调释放),再以非零退出——不再留下 PID 登记与孤儿进程。

**实测(复审验收口径)**:

1. **陈旧登记 + 并发启动**:预置陈旧 PID 文件后两个启动命令并发——胜者 200、登记=服务 PID,败者被「已有活跃测试服务」拒绝;`--stop` 成功关闭胜者(000)。
2. **日志路径目录阻塞**:阻塞时启动**退出码 1、无登记残留、无锁残留**;解除后重试启动成功(健康检查通过)且可正常停止。
3. **IPv6 替身**:替身监听 `::1:3211` 期间,测试服务在 `127.0.0.1:3211` 正常就绪(健康检查通过)并可 `--stop`——不再被 IPv6 监听者干扰为未就绪。
