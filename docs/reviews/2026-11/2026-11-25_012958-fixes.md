## WT-P3-002 · P1 · 后台并发无上限与取消盲区 —— 已修复

- **并发上限**：`MAX_ACTIVE=2`，超限返回 `busy-limit`（`busy-title` 语义保留：同标题在途仍复用）；紧急取消腾出配额后可再接新歌。
- **prune 保护**：只清理已结束任务（过期 30 分钟或容量超限最旧优先），活跃任务永不被映射删除——所有在途任务均可被 `cancelAll` 追踪。
- **编码可取消**：`encodeMp3` 增加 `AbortSignal` + 120s 超时，taskkill 树杀，停止后不遗留临时成片。
- **退出后再结算**：`runStep` 的 killTree 只置 `killReason`，`close` 事件到达才结算（强杀下 close 必达），清理与子进程退出不再重叠。

## WT-P3-003 · P2 · 成片堵死队列 —— 已修复

腾位候选纳入 `song`（与问候同级）：满队列时普通弹幕与高档答谢可挤出成片条目；淘汰记录 `capacity-evict-song`。高档答谢的小额腾位路径不受影响（其候选仍为礼物条目）。

## WT-P3-004 · P2 · 择源选错版本 —— 已修复

`rank()` 重写：查询词（歌名+歌手分词）每词命中 +2 / 缺失 −3（权重高于 GOOD 每词 +0.5），BAD 每词 −3；**最佳分 < 1.0（即无任何查询词可靠命中）直接拒绝**（"宁可不唱不唱错版"）。按审核用例回放：`篇章 乙歌手 MV` 同名甲乙中乙胜（6.5 vs 1.5）；无关 `其他歌 官方MV`（−3）不敌精确 `篇章 乙歌手`（1）。

## WT-P3-005 · P2 · 缓存键忽略配置与无容量约束 —— 已修复

## WT-P3-006 · P2 · 可保存的配置必致换声失败 —— 已修复

## WT-P3-007 · P2 · 先唱后确认与接单语义 —— 已修复

- `handleSongRequest` 重排：先入队确认条目，成功后才调 `requestSong`——缓存命中的同步成片回调此刻触发派发时，确认（40）已先于成片（35）。
- 确认语通过新增只读接口 `singing.peekCached(title)` 预判（"这就来/正在准备"），不再依赖 requestSong 返回值。
- 确认入队失败（满载）→ 不启动后台任务，接单结果=确认结果。
- 回归测试断言派发顺序：`plays[0]` priority 40（确认语）→ `plays[1]` priority 35（成片 audioUrl）。

## WT-P3-008 · P3 · 记录的 key 与实际不符 —— 已修复

## WT-P3-009 · P2 · Windows 子进程输出乱码 —— 已修复

三层：spawn 环境固定 `PYTHONIOENCODING=utf-8`；stdout/stderr 用 `StringDecoder('utf8')` 跨块解码；三个 Python 脚本 `sys.stdout/stderr.reconfigure(encoding='utf-8')` 双保险。
