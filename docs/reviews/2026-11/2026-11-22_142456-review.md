## WT-P2-013 · P2 · 音频故障后，已开始的冷场仍可能被打断

播放页拿到带音频的冷场后，音频加载失败或起播被拒时，仍会播放动画并显示字幕。服务端接受了动画 `started` 与音频 `failed`，但音频轨道仍存在，`opened()` 只读取其 `failed` 状态并返回 `false`。此时有观众互动，互动模块会停止正在展示的无声话题。音频已经收到 `started` 后再发生播放错误时，同一实现也会把已经开口的事实随轨道状态覆盖掉。[加载失败降级](../../../src/web/overlay/player.ts#L244) · [起播被拒降级](../../../src/web/overlay/player.ts#L275) · [播放期错误回执](../../../src/web/overlay/player.ts#L298) · [播放开始判定](../../../src/server/modules/playback/session.ts#L223) · [取消判断](../../../src/server/modules/interaction/index.ts#L222)

用实际 `createInteraction`、`createPlayback` 和可控时钟复验。以下各场景都先确认冷场仍是当前表演，再送入大航海并驱动一次调度。加载失败和起播被拒使用实际 `createPlayer` 与模拟媒体轨道，由播放器产生回执，其余场景使用模拟回执。

| 场景 | 新互动到达时的实测结果 |
| --- | --- |
| 动画已开始，音频尚未开始且仍可起播 | 冷场收到 `stop`，优先级 80 答谢接替，旧音频回执判为 `stale` |
| 音频 `started` 后自然 `ended`，动画仍在播 | 冷场继续，动画结束后答谢才接替 |
| 服务端因无租约派发无声冷场，动画已开始 | 冷场继续，动画结束后答谢才接替 |
| 播放页上报 `AUDIO_LOAD_FAILED` 或 `AUDIO_START_REJECTED`，动画已开始且字幕可见 | 两条路径均返回 `opened=false`，冷场收到 `stop`，答谢接替 |
| 音频 `started` 后上报 `AUDIO_PLAY_ERROR`，动画轨道仍在播 | `opened` 从 `true` 变回 `false`，冷场收到 `stop`，答谢接替 |

复验条件为播放会话在结算前一直保留已经收到的音频开始事实。若音频在起播前已失败并转成无声播放，则按动画是否已开始判定。音频仍在准备且尚可起播时，保留现有让位行为。回归用例应在同一表演尚未结算时送入观众事件，通过停止指令和接替顺序验证三个故障回执。[轨道状态更新](../../../src/server/modules/playback/session.ts#L158) · [现有取消回归](../../../src/server/modules/interaction/greetings.test.ts#L323)
