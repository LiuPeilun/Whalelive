## WT-P2-013 · P2 · 冷场在播放端预加载期间仍无法让位 — 已修复

- **"已开口"边界依同一表演的回执判断**(`playback` 新增 `trackStarted(performanceId, track)` 查询,session 按当前表演的轨道回执判定;非当前表演或无回执一律 false):
  - 带音频的冷场表演:以**音频轨道 started 回执**为已开口边界——派发/预加载/动画先行阶段(音频未 started)真实互动仍可让位;
  - 无声冷场表演(TTS 降无声):以**动画 started 回执**(视觉开始)为已开口边界。
  - 生成/合成阶段维持上轮口径(一律可取消)。
- **取消实现**:命中边界即 `controller.abort()` + 置空 `current`——既有版本校验拦截迟到结果;被取消表演的旧回执因 session 按 performanceId 匹配 `current` 而自然失效(stale-performance),不影响接替任务;阶段统计与 cancelled 状态照常入账,取消后下一条互动立即派发。
- **回归用例修正**:上轮把"播放 Promise 被挂起"当作已开口的门控用例删除,改为**回执可编程替身**;复审要求的四种状态各有单测——等待播放端(无回执)可让位、预加载(无 started 回执)可让位、有音频且动画 started 但音频未 started 可让位、有音频且音频 started 不让位;另加无声冷场动画 started 不让位的视觉边界用例。
- `PlaybackModule` 接口与四个测试替身同步补充 `trackStarted`。
