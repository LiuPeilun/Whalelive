## WT-P1-009 · 启动登记与就绪未绑定本次实例

**修复一:原子占用登记(`scripts/lib/test-server.mjs`)**

活跃 PID 检查与写入之间不再有窗口——登记文件的获取改为 `openSync(pidFile, 'wx')` **独占创建**(创建即占用该端口的启动权):

- 并发同时启动时只有一个进程能占用;败者读到占用文件,按「已有活跃服务(PID 存活且归属)/启动进行中(空占用文件)」拒绝,不再出现双方先后覆盖写入、败者退出误删胜者登记的竞态;
- 陈旧登记(进程已退出/PID 被复用)删除后重试占用;
- 占用后写入实际 PID;子进程退出时仅当文件内容仍是自己的 PID 才清理(被陈旧清理换主的文件不动);spawn 异常时释放占用。

**修复二:就绪与退出码绑定本次实例**

- **单进程启动**:`spawn` 改为 `node --import tsx <绝对入口>`(原 tsx cli 方式会 fork 出真正执行的服务子进程,端口监听者与 child.pid 不一致,任何基于 child 的核对都无法成立)。单进程下 child.pid 即端口监听者,命令行仍携带入口绝对路径(归属校验不变)。
- **监听者核对**:`waitHealthy` 要求 `Get-NetTCPConnection` 返回的端口监听者 PID === 本次 child.pid,且健康 200——普通实例占用端口时,本子进程 EADDRINUSE 退出且永远不会成为监听者,原实例的 200 不再被误判为本次启动成功;并发竞争的败者同理。
- **CLI 退出码**:`child.on('exit')` 以 `healthyReached ? 0 : 1` 退出——就绪失败(端口被占/崩溃)不再以 0 掩盖。

**实测(复审验收口径)**:

1. **同端口同时启动**:两个启动命令并发,败者拒绝(`已有活跃测试服务`),胜者 health 200 且登记=监听者同 PID,`--stop --port` 成功关闭胜者(000)。
2. **普通实例占用端口**:`npm start` 普通实例先占 3210 → 测试启动器**退出码 1**(不再打印"健康检查通过"式假成功)→ 普通实例继续可用(200)。
3. **既有场景回归**:顺序重复启动退出码 1 + 原实例登记保留可停止;不同端口并行日志互不覆盖(上轮已过,本轮结构未变)。
