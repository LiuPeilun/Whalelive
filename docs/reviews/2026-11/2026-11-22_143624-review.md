## WT-P2-013 · 关闭 · 音频故障后仍按已开始状态安排接替

有效的音频 `started` 回执会在同一会话中留下开始记录。音频随后结束或报错，记录会保留到表演结算。音频在起播前失败或服务端以无声方式派发时，`opened()` 依据动画回执判定。音频处于 `pending`、`ready` 时，观众互动仍可取消冷场。[回执更新](../../../src/server/modules/playback/session.ts#L154) · [已开始判定](../../../src/server/modules/playback/session.ts#L231) · [新增回归](../../../src/server/modules/playback/index.test.ts#L470)

专项复验将实际 `createInteraction` 与 `createPlayback` 连在一起，使用可控的服务端时钟。三条音频故障由实际 `createPlayer` 配合媒体轨道替身产生回执。每条用例都在当前冷场表演尚未结算时送入大航海，并检查停止指令与派发顺序。

| 场景 | 复验结果 |
| --- | --- |
| `AUDIO_LOAD_FAILED`、`AUDIO_START_REJECTED`，动画已开始且字幕可见 | 两条路径都没有发送冷场 `stop`，动画结束后才派发优先级 80 的答谢 |
| 音频已 `started`，之后上报 `AUDIO_PLAY_ERROR`，动画仍在播 | `opened()` 保持 `true`，动画结束后才派发答谢 |
| 音频自然 `ended`，或无租约降为无声且动画已开始 | 冷场继续，动画结束后才派发答谢 |
| 等待租约，或动画已开始但音频仍处于 `pending`、`ready` | 等待租约的冷场取消后未派发。已派发的冷场收到 `stop` 并让位，迟到的旧回执判为 `stale` |
| 音频在起播前报错，动画尚未开始 | 冷场收到 `stop`，答谢接替 |
