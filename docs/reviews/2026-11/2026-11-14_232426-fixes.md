## WT-P0-007 · P1 · 租约失效后旧会话未结束,后续任务被阻塞

**修复方式**:把"租约失效"与"该租约归属表演的终态"在服务端直接关联,覆盖全部三条失效路径——

- `src/shared/errors.ts`:新增稳定错误码 `LEASE_LOST`。
- `src/server/modules/playback/session.ts`:新增 `leaseLost(leaseId)` —— 派发时携带该租约的当前表演立即结算为 `failed(LEASE_LOST)`,并经 `sendStop` 通知播放端本地停止;结算校验仍基于会话记录的 `runId` / `leaseId` / `performanceId` / 派发归属,迟到回执按既有幂等规则失效。
- `src/server/modules/playback/renderer-lease.ts`:`sweep()` 返回本次回收的租约 ID。
- `src/server/modules/playback/index.ts`:三条路径接入 `leaseLost` —— ① 调度心跳回收过期租约;② 持有者主动 `releaseLease`;③ 新播放端接管已过期租约(比较接管前后的租约 ID)。

由此 interaction 收到唯一终态 Promise 后立即推进队列,不再依赖 120 秒整体看门狗;播放端断线(`RENDERER_LOST`)路径保持不变。

**回归用例**:

- `session.test.ts` 新增 2 例:leaseLost 结算 failed(LEASE_LOST) + 补发停止 + 迟到回执失效;无关租约的 leaseLost 不影响会话。
- `index.test.ts`(新文件)2 例联动回归:租约到期 → 结算 LEASE_LOST + stop 下发 → 旧回执失效 → 重新取得新租约后下一表演立即派发并以新租约正常完成;持有者主动释放租约同样立即结算。

**验证**:新增 `scripts/lease-lost-e2e.mjs`(协议级,复现审核场景:临时收紧租约 ttl 3000 / 续租 1000,播放端停止续租,验证 stop 下发、会话结算、队列继续、新租约下 wave 完成、旧回执失效,结束后恢复原设置)。**13/13 通过,背靠背 3 轮稳定**。

## WT-P0-009 · P2 · 待机未加载时派发动作,结束后无法恢复正确待机

**修复方式**:消除缓冲位复用竞争——

- `src/web/overlay/video-track.ts`:缓冲位按角色固定——位 0 恒为待机(`prepareIdle`,媒体元素自身 `loop` 持续循环)、位 1 恒为表演动作(`prepareAction`,"一轮即结束")。待机预加载与动作派发交错时落在不同元素,不再出现地址与循环配置互相覆盖。
- `src/web/overlay/player.ts`:待机片段缓存引入**代数 + playToken 双守卫**——待机预加载完成晚于表演派发时不覆盖进行中的表演,缓存保留供回待机使用;待机素材加载失败后回到待机时按需懒重建;同一素材的重复 `setIdle` 沿用既有缓存。

**验证**:新增 `scripts/e2e-late-idle.mjs`(CDP `Fetch` 拦截延迟首个 idle.webm 请求 3 秒,期间立即派发 dance,再放行待机请求):dance 在专属缓冲位播放,结束后页面显示 idle.webm、`loop=true`、非暂停、无占位框;随后再次派发动作并再次正确回待机。**通过**(截图 `.tools/e2e-late-idle.png` 证实透明待机画面)。

## 测试基建附带修复(验证稳定性)

验证过程中发现并修复了三类**测试脚本自身**的干扰(均已随本分支提交):

1. e2e 脚本的 Edge 进程清理:`edge.kill()` 与 `taskkill /T` 在本机都杀不干净 Chromium 进程树,残留页面会重连 `/ws` 持续续租占住租约(干扰 007 验证)。改为:**独立 `--user-data-dir`(规避 Chromium 单实例转发)+ `taskkill /T` + PowerShell 按 profile 过滤兜底强杀**;全套运行后实测残留为 0。
2. `lease-lost-e2e` 的回执校验:回执必须携带服务端分配的 `rendererId`;`waitFor` 增加起始下标,租约申请只匹配本次请求之后的新消息(曾把 dance 阶段的旧租约结果误当新租约)。
3. 断言语义:"队列不被阻塞"由瞬时快照改为轮询等待(遗留礼物表演会紧随其后自愈派发并结算,瞬时读数会误报);对非 dance 的遗留派发按真实页面行为自动回执自愈;弹幕提交以唯一用户避开 10 秒冷却并自动重试。
