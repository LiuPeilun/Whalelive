## WT-P0-007 验证

### 续租被拒后恢复

隔离配置使用 ttlMs=3000、renewIntervalMs=1000。dance 播放时仅抑制续租发送，提前排入 wave。旧租约回收后 dance 立即结算，wave 以派发身份正常起播。恢复旧租约续租发送，页面收到 LEASE_EXPIRED，随后自行发送新的 lease-request 并取得租约。wave 在重新取得租约期间继续播放，最终 ended 并回到循环 idle。

关键观察结果如下。

```text
dance settled failed LEASE_LOST
wave dispatched leaseId=null
lease-result LEASE_EXPIRED
lease-request -> new lease granted
wave settled ended
```

### 首次申请被拒后接管

页面 A 持有并持续续租。页面 B 登记后收到 LEASE_HELD，在等待期间按退避重新申请，A 的持有权保持有效。关闭 A 后，B 自动取得新租约。B 随后执行 wave，服务端正常 ended，页面回到 idle。

本轮实际观察到 B 在约 2.3 秒内已发送 3 次申请，关闭 A 后约 3.6 秒取得租约。该时序与首次立即重试、随后退避的实现一致。

## WT-P0-011 验证

使用隔离本机 TCP 服务接收首个业务握手并保持不回应，真实 Edge 的首个业务 WebSocket 保持 CONNECTING。10 秒守卫到期后允许后续连接进入正常 WhaleTalk 服务。

恢复后页面观察到的状态如下。

```json
{
  "openBusinessSockets": 1,
  "rendererCount": 1,
  "reconnects": 1,
  "lastError": "connecting-timeout"
}
```

随后提交 dance，服务端播放状态进入 playing，收到实际动画终态后结算为 ended，页面回到循环 idle。关闭页面并等待后，服务端播放端数量为 0。

源码核对确认重连调度具有唯一计时器，超时会使旧连接代数失效，替换连接时关闭并解除旧连接事件，迟到消息按连接代数过滤。此次验证没有重现上轮的重复登记和 stale-owner。
