## WT-P1-021 · 直播自动回退仍使用主动选择固定回复的来源标记

**修复(`reply-router.ts` generate)**:自动降级统一标记来源 `fallback`,与主动选择 `fixed-local` 可区分——

- 选了 DeepSeek 但**缺 Key**:降级返回 `{ ...fixed, provider: 'fallback' }`(用户选择的是 deepseek,模型未参与即属降级);
- **上游故障/超时/输出不可用**:catch 中降级同样标记 `provider: 'fallback'`;
- 主动选择 `fixed-local`:原样返回 `provider: 'fixed-local'`(withProviderLabel),不变。

队列区 `metrics.last.provider` 直接来自该标记,操作者可从 `fallback` 判断该条回复是模型故障降级(与 P1 验收条目一致)。

**复验(复审要求的三状态,单测 + 离线端到端)**:

| 状态 | 断言 | 结果 |
| --- | --- | --- |
| 缺 Key | 降级结果 `provider === 'fallback'` | ✓ |
| 上游故障(HTTP 401) | `provider === 'fallback'` | ✓ |
| 主动离线 | `provider === 'fixed-local'` 不变 | ✓ |
| 模型成功 | `provider === 'deepseek'` 不变 | ✓ |

## WT-P1-022 · 真实适配器仍丢弃非法或截断回复的 token 用量

**修复(适配器 + 类型化错误 + 路由保留)**:

- `providers.ts` 新增 `ReplyInvalidError`(携带可选 `usage`)——语义为「上游响应已取得但输出不可用」;
- `deepseek.ts` 在 **JSON 解析后立即读取 `readUsage(raw.usage)`**(原先在校验通过后才读),截断/空内容/非法 JSON 三条错误路径以 `ReplyInvalidError(message, usage)` 抛出——usage 随错误上行不再丢失;
- `reply-router.ts` 降级时从类型化错误读回 usage,并入保底结果(`{ ...fixed, provider: 'fallback', usage }`)——interaction 既有记账逻辑(`result.usage` 归属本次请求)无需改动即生效。

**回归(复审验收口径:真实适配器 + 假端点)**:

1. HTTP 200 + 非法 JSON + 32 token → 保底内容、`provider: 'fallback'`、`usage = {20/12/32}` ✓;
2. HTTP 200 + `finish_reason=length` + 32 token → 同上,截断不丢用量 ✓;
3. 合法回复 + 32 token → `provider: 'deepseek'`、usage 照常 ✓(既有行为不变)。

**直播入口级复验(`e2e-llm.mjs` 假 Key 场景扩展)**:假端点改为有状态——第 1 次(预览)返回合法回复,第 2 次起(直播弹幕)返回非法 JSON + 32 token。真实模拟弹幕入口实测:来源标记 `fallback` ✓、**累计用量精确增加 32** ✓。
