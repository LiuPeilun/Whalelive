## WT-P0-007 · P2 · 续租被拒后取消了全部租约恢复入口

**根因确认**:上轮修改删除了 lease-result 失败分支原有的延迟 `lease-request`,而 `dropLeaseAndStopIfHeld` 同时清空两个租约计时器,导致"续租被拒"与"首次申请被拒(LEASE_HELD)"两条路径都失去重申请入口。

**修复方式**(`src/web/overlay/main.ts`):新增 `scheduleLeaseRequest()` —— 唯一待执行计时器 + 指数退避(首次立即,此后 2s 起倍增至 15s 上限),申请前核对页面尚未持有租约;接入:

- lease-result 失败分支(续租被拒 / 首次被拒共用);
- 本地看门狗路径(原立即发送改走同一入口);
- 成功取得租约、重新登记、断线、页面关闭四个时机复位/清理,重试生命周期完整。

**回归用例**:新增 `scripts/e2e-lease-takeover.mjs`(真实双浏览器,覆盖审核验收方向):页面 A(leaseholder profile)取得并持有租约;页面 B(leasetaker profile)登记后首次申请被拒(服务端新增 `ws.lease-denied` 观测日志佐证)→ A 存续期间租约不被抢走 → **关闭 A** → B 按退避重试自动接管租约 → 提交 wave 在新租约下正常完成。**7/7 通过**(接管后 `leaseHolderRendererId` 更新为 B、会话回到空闲)。页面实现的真实重申请能力由此在浏览器级证实(审核指出的"协议脚本通过不能证明页面实现"已补齐)。

## WT-P0-011 · P2 · 连接超时与 close 重复排队,产生两个业务连接并破坏回执归属

**根因确认**:守卫触发后浏览器对 `close()` 异步派发的 close 事件再次调用 `scheduleReconnect`(无幂等),产生两条并行重连;且旧连接的 `onmessage` 缺少连接代数检查,继续更新页面全局状态,发送却走最新 socket,回执归属与服务端派发不一致。

**修复方式**(`src/web/shared/ws-client.ts`):

- **唯一待执行重连计时器**:`scheduleReconnect` 幂等(reconnectTimer 已置位即返回),`connect` 执行时清零——同一次失败只进入一次调度,守卫路径与浏览器异步 close 路径并发收敛为一次。
- **全 handler 连接代数失效**:`onopen` / `onmessage` / `onclose` / `onerror` 均检查会话编号,被替换连接的迟到事件(含竞态窗口内迟到的成功握手)直接失效并自行关闭。
- **connect 即替换并关闭残存连接**:新连接建立前显式解绑旧 socket 全部事件并 `close`,杜绝同页第二业务连接。
- 用户 `close()` 清理重连计时器,退出生命周期完整。

**回归用例**:新增 `src/web/shared/ws-client.test.ts`(3 例,FakeWebSocket 替身忠实复现浏览器异步 close:close() 置 CLOSING、close 事件由测试择时派发;已中止连接不派发 open):

1. 守卫触发 + 异步 close → 仅一次重连、一个新连接;旧连接迟到的消息/close 失效;
2. 守卫后重复/紧随的 close 幂等,不产生并行重连,连接稳定;
3. 迟到 open 被关闭且不发送认证,不成为同页第二业务连接。

**结果**:41/41 全过(38 + 3 新增)。
