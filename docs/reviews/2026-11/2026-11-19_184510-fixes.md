## WT-P1-021 · 预览吞掉上游故障,控制台无法判断模型是否可用

**问题回顾**。直播与预览共用回复路由,路由捕获 DeepSeek 异常后返回带 `fixed-local` 标签的正常回复,HTTP 层的 LLM 错误码形同虚设;选 DeepSeek 缺 Key 与主动选固定回复显示相同标签。

**修复**。区分直播降级与预览诊断两条路径:

- `reply-router.ts` 新增 `generateStrict`(预览专用,不吞异常)与 `diagnose`(配置诊断)。直播仍用 `generate`,保留缺 Key/调用失败自动降级固定回复;预览遇缺 Key 抛 `LlmPreviewError(NOT_CONFIGURED)`,HTTP 失败抛 `UPSTREAM_ERROR`,超时抛 `TIMEOUT`,不再伪装成固定回复。
- `diagnose()` 返回 `requested/active/configured/fallbackReason`;选了 DeepSeek 但缺 Key 时 `fallbackReason=DEEPSEEK_KEY_MISSING`,与主动选择固定回复(null)区分。
- HTTP `GET /api/llm/config` 暴露 `fallbackReason`;`POST /api/llm/preview` 改用 `generateStrict`,`sendLlmError` 按 `LlmPreviewError.reason` 映射 502 `LLM_UNAVAILABLE` / 504 `LLM_TIMEOUT`。
- 控制台配置状态在回退时显示「回退原因:服务端未配置密钥」。

[回复路由](../../../src/server/integrations/llm/reply-router.ts) · [HTTP](../../../src/server/transport/http/index.ts) · [面板](../../../src/web/control/features/settings-panel.ts)

**实测**。单测 5 项(主动 fixed 无回退原因、缺 Key 预览报错但直播降级、401 抛 UPSTREAM_ERROR、超时 TIMEOUT、正常走模型);e2e 诊断场景确认配置暴露 `DEEPSEEK_KEY_MISSING`、缺 Key 预览返回 502 + `LLM_UNAVAILABLE`。

## WT-P1-022 · 生成耗时被重复计入排队,部分终态漏记用量

**问题回顾**。排队耗时从入队算到模型完成,模型时长同时计入排队与生成;规则语音回复合成耗时为空;用量只在播放结算时累计,模型响应后停止、非法输出抛错时用量丢失。

**修复**。重排计时与用量归属:

- `CurrentTask.timings` 改为每阶段独立起止:`dequeuedAt`(出队)、`generationDoneAt`、`synthesisStartAt`、`synthesisDoneAt`、`playbackAt`。排队=出队-入队;生成=生成结束-出队;合成=合成结束-合成开始;播放=终态-播放开始,互不重叠。
- 规则回复也设置合成起点,合成耗时可观测;无生成阶段时 `generationMs` 为 null。
- 用量在取得模型结果时即按本次请求累计一次(在版本检查前),与播放终态解耦——响应后停止、非法输出走保底都如实计入;播放终态不再重复累计。停止时把当前任务的阶段统计与已取得用量写入 `lastMetrics`,避免迟到终态被丢弃后无记录。
- provider 标记:成功取用时用提供方标识,走保底时固定标记为 `fallback`,不再被上游 `provider` 覆盖。

[interaction](../../../src/server/modules/interaction/index.ts)

**实测**。单测新增:规则语音合成耗时非空、非法输出仍计 32 token、响应后停止仍计入并留统计、排队耗时不含生成的 500ms(可控时钟)。15 项 interaction 测试全通过。

## WT-P1-023 · 默认模型、思考开关及截断状态未按 DeepSeek 契约处理

**问题回顾**。未设模型时发送 `deepseek-chat`(契约约定 `deepseek-flash`);关闭思考时出站没有 `thinking` 字段,取决于上游默认;`finish_reason=length` 但内容含完整 JSON 时仍按成功返回。

**修复**。按 ARCHITECTURE §6 冻结契约修正:

- `app.ts` 默认模型 `deepseek-chat` → `deepseek-flash`(本地兼容端点仍可由 `DEEPSEEK_MODEL` 覆盖)。
- 思考开关始终显式发送:`thinking: { type: 'disabled' | 'enabled' }`,不依赖上游默认。
- 识别 `finish_reason === 'length'`:即使内容可解析出 JSON 也判为截断、抛错走保底;仅在该字段明确为 `length` 时判定,缺失该字段的自定义兼容端点保持原样处理。

[app.ts](../../../src/server/app.ts) · [deepseek.ts](../../../src/server/integrations/llm/deepseek.ts)

**实测**。单测新增/更新:关闭思考显式发 disabled、`length` 完整 JSON 仍回退、`stop` 正常返回、无 finish_reason 兼容、思考开启发 enabled。22 项 deepseek 单测全通过。

## WT-P1-024 · 标称离线的端到端检查仍调用在线 Edge TTS

**问题回顾**。`e2e-llm.mjs` 仅清空模型 Key,服务沿用默认 `edge-tts`;受控挂起 Edge 握手时模拟弹幕卡在合成,统计轮询先耗尽导致 3 项失败。

[e2e-llm.mjs](../../../scripts/e2e-llm.mjs)

**实测**。`node scripts/e2e-llm.mjs` 三个场景全部通过(零配置 11、假 Key 4、诊断 3),不依赖任何外部语音服务。
