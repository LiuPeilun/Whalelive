## WT-P3-002 · P2 · 编码超时或失败时仍遗留临时 MP3

用真实 Windows FFmpeg 复验了急停。部分数据已写入后发送取消，任务先处于 `cancelling`，FFmpeg `close` 后进入 `failed`，临时 MP3 已删除，且没有发布成片。无操作者取消时的异常分支仍只调用 `fail()`。分别让编码替身写入 4096 字节后以 `encode timeout after 120000ms` 和 `ffmpeg exit=1` 结束，真实唱歌模块在两条路径均删除工作目录并进入 `failed`，缓存目录中仍各留一个临时 MP3。复验需用相同收尾覆盖急停、编码超时、进程报错和发布失败，等进程退出后检查两个目录。[临时路径与编码](../../../src/server/modules/singing/index.ts#L156) · [异常分支](../../../src/server/modules/singing/index.ts#L180)

## WT-P3-004 · P2 · 只剩纯伴奏或没有核心词时仍进入下载

上一轮多词歌名配错歌手的案例现已在下载前拒绝。新增硬过滤同时移除了最低置信门槛，导致低分候选也能直接成为首选。以实际 Python `main()` 回放固定搜索结果，查询 `篇章 张韶涵` 时只提供 `篇章 张韶涵 纯伴奏`，分数 `-2`，仍调用下载。输入 `官方 MV` 时核心词为空，唯一候选 `无关教学视频` 同样进入下载。两个案例均以下载替身确认入口，没有下载这些候选。复验需在核心词匹配之外，覆盖无实际歌名、只有纯伴奏和没有可靠候选的请求。[核心词过滤与评分](../../../scripts/song/steps/fetch.py#L45) · [下载前判断](../../../scripts/song/steps/fetch.py#L89)

## WT-P3-006 · P2 · 时长和目标音高仍可保存小数，实际会取整

全新目录四项比例仍为 `0.4 / 0.3 / 0.33 / 0.25`，合法比例可保存、回读并原样到达管线。旧版 40 秒限制为 24 秒。设置 schema 对 `clipSeconds`、`targetHz` 仍允许有限小数，读取迁移却将两者取整。实际 `PUT` 提交 `10.4` 秒及 `310.4` Hz 返回 `200`，随后 `GET` 和后台任务均用 `10` 秒及 `310` Hz。复验需统一保存契约、回读和实际生效值，并保留旧超长片段迁移与合法比例处理。[保存校验](../../../src/server/modules/settings/schema.ts#L122) · [读取取整](../../../src/server/modules/settings/index.ts#L88)

## WT-P3-007 · P2 · 接单结果和确认语仍可与实际受理不一致

后台两条冷管线挂起时，缓存歌曲现已成功入队。第三首新歌会正确返回 `accepted:false, reason:song-busy-limit`，但同时排入「正在准备」及「现在唱歌排满了」，措辞仍自相矛盾。用实际 HTTP 紧急停止后，在首个任务仍处于 `cancelling` 时再次点同名歌，接口返回 `accepted:true`，没有启动新任务，旧任务退出后也没有歌曲入队。去重条件仍复用即将取消的任务。[发送确认与繁忙提示](../../../src/server/modules/interaction/index.ts#L429) · [同标题复用](../../../src/server/modules/singing/index.ts#L204)

另以五条同优先级普通弹幕填满暂停的待播队列，再点一首缓存歌曲。优先级 40 的确认语成功排入，优先级 35 的歌曲返回 `queue-full`，但点歌接口仍报 `accepted:true`，队列没有歌曲。复验应区分确认语、后台任务和待播歌曲的实际受理状态。覆盖繁忙时单一真实提示、急停后同名重试，以及缓存命中遇到待播队列满的结果。[成片回调](../../../src/server/modules/singing/index.ts#L228) · [成片队列结果](../../../src/server/modules/interaction/index.ts#L465)

## WT-P3-005 · 关闭 · 排队和在播媒体可抵抗缓存淘汰

旧缓存成片通过真实 HTTP 点歌进入暂停队列。持续写入 52 个不同成片，跨过歌曲缓存硬限，原音频 `HEAD` 仍为 `200`。启动播放并持有租约，再填入旧的共享音频、触发通用缓存淘汰，原音频依然可读。模拟两轨结束回执后再次写入，已无引用的旧缓存被移除，`HEAD` 变为 `404`。实际应用的两个缓存均接入同一播放引用查询。[应用接线](../../../src/server/app.ts#L98) · [引用查询](../../../src/server/modules/interaction/index.ts#L949)
