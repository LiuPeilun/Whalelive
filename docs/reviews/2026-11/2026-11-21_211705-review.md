# P2 互动玩法第一批代码审查

本轮发现 1 项 P1 和 2 项 P2。优先修复普通弹幕能派发最高档答谢动作的问题。控制台试播沿用单表演、单动画与单音频轨道，和现有架构兼容。本地角色清单的 19 个动作素材与循环标记均通过核对。

## WT-P2-001 · P1 · 普通弹幕可派发「盖章寄信」

已确认的互动方案将 `stamp-letter` 保留给最高档答谢。当前装配将所有素材存在的动作交给 DeepSeek，提示只排除 `idle`。模型返回 `stamp-letter` 后，适配器和互动层都按角色清单的存在性接受，普通弹幕由此派发与付费仪式相同的动作。[候选集合](../../../src/server/app.ts#L96) · [生成候选](../../../src/server/integrations/llm/deepseek.ts#L96) · [互动层采纳](../../../src/server/modules/interaction/index.ts#L350)

隔离服务用本地假模型返合法回复及 `action: "stamp-letter"`，提交普通模拟弹幕「今天海边的风大吗」。核对请求的提示含 `stamp-letter`，服务端最终记录 `interaction.dispatch` 的动作是 `stamp-letter`，优先级为 40。

修复验收要求按触发来源限制可用动作。普通弹幕的提示与结果采纳均排除答谢专属动作，保留回复文本并回落到普通说话。控制台仍可手动试播，最高档规则接入后可以独立派发该动作。

## WT-P2-002 · P2 · 缺素材的动作仍可被模型采纳和手动试播

模型提示依据 `available` 构造候选，返回动作的校验只判断清单是否登记。模型输出缺文件的动作后会覆盖原本可用的默认说话动作。手动接口也只判断是否登记，控制台会显示「素材缺失」但仍允许选中和提交，并在 HTTP 成功后提示已试播。[提示与采纳](../../../src/server/integrations/llm/deepseek.ts#L150) · [试播输入](../../../src/server/transport/http/index.ts#L239) · [试播下拉框](../../../src/web/control/features/manual-action.ts#L24)

隔离实例启动前仅在测试副本中省略 `spin.webm`。`GET /api/control/character` 返回 `spin.available=false`，系统提示无 `spin`。假模型返回后，互动仍以 `spin` 派发并记录 `interaction.asset-missing`。手动试播该动作也返回 HTTP 200、`accepted: true`。同一不一致适用于 `idle`，模型提示排除了它，假模型选择它时预览仍返回 `action: "idle"`。

修复验收要求模型结果经由与实际候选一致的动作集合验收。候选之外的结果保留文本和默认动作。试播下拉框禁用或过滤缺失项，直接调用试播接口也要得到清楚的素材缺失反馈。当前日常角色包的 19 个文件均存在，该项针对迁移、分批复制或素材缺失的情况。

## WT-P2-003 · P2 · 带口令词的问题仍可被旧的包含匹配截获

「敬个礼」「喝口茶」新增了整句匹配。整句不匹配时仍会进入旧的包含匹配，其中「为什么」无条件触发 `think`。第一批约定的「含口令词的正常提问进入问答」在该边界没有成立。[口令与旧规则](../../../src/server/modules/interaction/rules.ts#L21) · [已有回归样例](../../../src/server/modules/interaction/rules-phrase.test.ts#L147)

经真实模拟弹幕入口提交「为什么要喝口茶？」，服务派发 `think` 并使用固定台词「让我想想……再想想……」，假模型请求数增量为 0。正向对照「敬个礼」派发 `salute` 且请求数增量同样为 0。

修复验收要求区分完整口令、明确的旧动作指令和普通提问。在已有含词样例之外，用带「为什么」的喝茶提问复验问答路径，并保留两个独立彩蛋口令的正向断言。旧包含规则早于本批存在，本问题记录它与新验收要求的冲突。
