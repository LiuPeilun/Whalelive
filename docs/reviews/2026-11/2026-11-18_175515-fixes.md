## WT-P1-004 · 断线注销清除了接管安全等待

**修复一(服务端,`renderer-lease.ts`)**:`unregister()` 在删除租约前记录 `lastExpiredSafeUntil = now + takeoverSafetyMs`,与 `sweep()` 定时回收走同一转交约束——断线属于"未确认停声"(旧页要到本地 `onclose` 才停声),新端须等安全时刻才可发声。申请路径(有租约与无租约两分支)统一比较 `expiresAt + takeoverSafetyMs` / `lastExpiredSafeUntil`。

**修复二(页面,`overlay/main.ts`)**:`beforeunload` 先执行 `player.stopAll()` 完成本地停声,再发送 `lease-release`——显式释放对应"停止确认已完成",新端零等待接管符合契约;页面关闭路径的释放不再出现"先释放后停声"窗口。

**单测**(`index.test.ts` 断线时序):`unregister` 后 t=1000 新端申请被拒(LEASE_HELD,窗口内),t=1801 接管成功(安全窗 800ms + 可控时钟)。

**实测**(`scripts/e2e-disconnect-safety.mjs`,真实 WS `terminate` 触发服务端 close 清理路径):

- A 取得租约 → A 硬断 → B 立即申请:**被拒(LEASE_HELD)** → 安全时刻后再申请:**授予**;
- 显式释放(lease-release)后新端:**零等待接管**。

复审要求的三条路径:到期回收(上轮复审已验证)、延迟处理断线(本轮服务端安全窗 + 实测)、先停声再显式释放(本轮页面顺序保证 + 实测)全部覆盖。

## 计划外 · 复测暴露的页面重连自愈(重连后状态同步)

复测 `e2e-reconnect-idle.mjs stage2`(服务重启后无互动恢复待机)持续失败。逐层排查证据:

- 服务重启后健康,raw Node WS 立即握手成功(服务端升级处理无辜);
- 卡住页面内 `fetch('/api/health')` 返回 200(HTTP 栈正常),`new WebSocket` 到坏端口 3999 立即 error(网络栈正常),**唯独到 `127.0.0.1:3210` 的 WS 永久 CONNECTING**(换 `localhost` 主机名同样卡);
- 服务端日志收不到页面的升级请求;页面不重载则 65s+ 不恢复,**重载页面立即恢复**。

定性:服务进程被硬杀后,Edge/Chromium 对该地址的 WS socket 层整体卡死(握手请求被扣,不出网络栈)。业务重试无法穿透;生产形态下(OBS 常驻页面 + 用户重启服务)将表现为"重启后直播画面永不恢复"。ws-client 状态机本身无过错(事件轨迹逐条核对,守卫与调度均正确)。

**修复(`ws-client.ts`)**:连续 3 次"握手悬挂守卫"触发(每次 10s,退避拉长)时执行 `location.reload()` 重建网络栈;凭据在 URL fragment,重载即恢复。防风暴:`sessionStorage` 记录重载时刻,30s 内已重载过则退回纯重试。服务真宕机时握手是快速 error(TCP 拒绝),不累计悬挂,**不会误触发重载**。服务正常时 `open` 将悬挂计数归零。

**实测**(`scripts/e2e-selfheal-verify.mjs`,完整竞态复现):杀服务→重启→卡死复现(连续悬挂守卫)→第 3 次悬挂触发重载(`wtWsReloadAt` 时间戳落盘)→新文档单次握手成功→**约 47s 待机自动恢复**,全程无人工干预。`e2e-reconnect-idle.mjs` stage2 观察窗 25s→70s 覆盖该时序后完整通过。
