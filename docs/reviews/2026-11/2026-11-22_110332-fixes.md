## WT-P2-006 · P2 · 高档答谢已入队,仍被写入丢弃记录 — 已修复

- **记录职责上移**(`queue.ts`):`push` 不再自行记录 `queue-full`——腾位/合并调用方可能重试成功,首次失败的记录会残留为"已入队却显示已丢弃"的误报。最终拒收由 interaction 层既有路径统一记录(`recordReject` 写入 rejectLog,与队列丢弃记录合并展示),审核指出的"确认最终拒收时才记录"落地。
- **覆盖全部 queue-full 路径**:普通聊天、大航海/醒目留言、模拟礼物结算、人工试播、合并产物入队的最终拒收均已经由 `recordReject` 记录;本轮补齐了合并放回路径(合并入队失败后原答谢放回,放回失败同样记录),无静默丢失。
- **保留的队列内部记录**:`expired`/`expired-on-arrival`/`capacity-evict-chat`/`capacity-shrink`/`stopped`/`peak-merged`/`displaced-for-high-tier` 属于队列自身生命周期或已定案事件,维持原状。
- **审核复验口径**(单测):16 批场景下三条高档答谢的事件 ID 不再出现于丢弃记录,仅剩三条被取代小额的 `displaced-for-high-tier`;queue 模块契约测试同步更新("满载拒收不写入丢弃记录"),两个满载用例均新增"已接受事件 ID 不入丢弃记录"断言。
