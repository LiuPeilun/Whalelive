## WT-P1-014 · P2 · 调用者的协调端口环境变量会让隔离回归失败

场景 3 向临时目录写入固定协调端口 32295，却仅覆盖子进程的 `WHALETALK_TOOLS_DIR`，原样继承调用者的 `WHALETALK_STARTLOCK_PORT`。当调用者用合法的自定义端口启动日常测试服务时，两个回归子进程都会在读取隔离配置时因端口不一致退出。场景预期的是两个启动器使用同一配置并竞争启动。[临时配置与子进程环境](../../../scripts/e2e-startlock-regression.mjs#L196) · [配置冲突检查](../../../scripts/lib/test-server.mjs#L114)

在隔离副本将调用者端口配置和环境变量都设为 8870，运行原版回归脚本。场景 3 两个启动器均退出 1，胜者、健康和停止三个断言失败，整套脚本退出 1。单独以相同环境启动场景 3 的子进程，确认错误为端口配置不一致，未生成服务日志。回归后调用者配置保持字节一致，原环境下常规 CLI 启动返回 HTTP 200，停止退出 0。[场景 3 断言和停止](../../../scripts/e2e-startlock-regression.mjs#L232)

场景 3 应为两个子进程显式设置与临时文件匹配的协调端口，或清除该继承变量，让它们读取临时文件。复验覆盖环境变量未设置和与调用者工作区一致的自定义值两种情况。
