## WT-P1-020 · 租约失效回归中断后留下临时语音和租约设置

**问题回顾**。原 `scripts/lease-lost-e2e.mjs` 默认连接已有服务，运行时用 PUT 把被测服务设置改为短租约 + `fixed-local`，结束阶段再 PUT 写回。测试尾部之前报错或被强制终止时，写回无法执行，日常实例停留在临时语音与租约配置；正常结束时还可能覆盖测试期间另行保存的设置。

**修复**。沿用晚待机脚本 `e2e-late-idle.mjs` 的隔离方式改造租约脚本：

- 脚本通过 `createApp`（`tsImport` 直载 `src/server/app.ts`）在自身进程启动独立服务，数据目录为系统临时目录下的 `whaletalk-lease-lost-*`，`PORT: '0'` 由系统分配回环端口，`HOST: 127.0.0.1`、`PLATFORM: mock`。服务与脚本同进程，强制终止即释放端口，全程不读取项目 `data/access.json`，也不连接日常实例。
- 短租约（`ttlMs 3000` / `renewIntervalMs 1000` / `takeoverSafetyMs 0`）与 `tts.provider: fixed-local` 预置在隔离数据目录的 `config/settings.json`（`savedVersion: 1`），由服务启动加载，不再经 HTTP 写入任何被测服务。占位动画复制到同一临时目录供派发条件使用。
- control / playback 凭据从 `app.urls.control`、`app.urls.overlay` 的 `#` 片段提取，服务地址用 `app.urls.base`，来源校验与实际端口一致。
- 删除脚本开头对已有服务的 `resume` 与遗留任务等待、结尾读取最新版本并整份回写原设置的逻辑。隔离服务随脚本退出关闭，无回写对象，也就不会覆盖其他保存。
- 保留全部协议级断言：租约回收后 `stop` 下发、`wave` 自动推进、按派发身份回执完成、续租失败后重取租约、迟到回执失效；新增一项启动预置核对（短租约 + fixed-local + `savedVersion === 1`）。

[回归脚本](../../../scripts/lease-lost-e2e.mjs)

**实测**。

- 正常运行：`node scripts/lease-lost-e2e.mjs` —— 隔离服务端口 48542，`10 通过 / 0 失败`，含新增预置核对与原有五项 WT-P0-007 断言；租约 `ttlMs 3000` 生效，`lease-expired → lease-lost → session-settled(LEASE_LOST) → wave 自动推进 → wave ended → report-stale` 链路完整。脚本正常退出后端口释放。
- 强制中断：后台启动脚本，等到打印“PASS 隔离实例预置短租约与本地语音”（隔离服务端口 52560、dance 已派发）后 `kill -9` 脚本进程，进程随即终止。核对并行运行的日常实例 3210：`savedVersion` 仍为 174、`tts` 仍为 `fixed-local` / `zh-CN-XiaoxiaoNeural`、租约仍为 `15000 / 5000 / 800`，与中断前一致；项目根 `data/config/settings.json` 与 `data/access.json` 的 sha256 分别为 `6e17bb…`、`bac78f…`，与基线逐字节相同；隔离端口 52560、48542 均已释放。
- 修复前同一场景会留下 `fixed-local` 与租约 `3000 / 1000 / 0`、`savedVersion` 由 1 变 2；本轮验证中日常实例三项设置与版本均未改变。
