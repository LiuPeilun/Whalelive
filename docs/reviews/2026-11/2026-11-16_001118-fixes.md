## WT-P0-007 · P2 · 租约回收后自动派发下一任务,回执租约不匹配

**根因**:页面回执的 `leaseId` 取自页面全局租约变量,而服务端校验依据是**该表演派发时的租约快照**。自动推进的下一项派发于租约回收后(快照为空),页面却带着未过期的旧租约回执 → `stale-lease` → 会话挂至看门狗。页面本地看门狗/续租失败分支还会无条件停止当前播放,误杀以新身份派发的表演。

**修复方式**:回执与本地停止全部绑定**派发身份**——

- `src/web/overlay/main.ts`:新增 `currentDispatchLeaseId`(当前表演派发时的租约快照);`performance` 消息登记、`stop` 消息清空、断线清空;`report` 回执改用该快照而非全局租约。
- `dropLeaseAndStopIfHeld(lostLeaseId)` 改为按归属过滤:仅当进行中表演以失效租约派发时才本地停止,空租约/新租约派发的表演(自动推进)继续播放;续租失败分支传入失效租约 ID,本地看门狗按同一过滤执行后立即重新申请租约。
- 服务端无需变更:`PlaybackDispatch.leaseId` 即派发身份快照,校验链原样工作。

**回归用例**:

- `index.test.ts` 新增 1 例(审核指出的缺失顺序):**租约失效前不重新取租约**,dance 结算 LEASE_LOST 后自动推进的 wave 以 `leaseId=null` 派发,页面按派发身份回执 → accepted → 正常完成;旧租约回执保持 stale。
- `scripts/lease-lost-e2e.mjs` 主流程重写为审核场景:wave 在 dance 租约失效**之前**入队 → 停止续租 → dance 结算 + stop 下发 → wave 自动推进(`leaseId=null`)→ 以派发身份回执并完成 → 模拟页面续租失败(LEASE_EXPIRED)按归属过滤不误停、重新取得新租约 → 旧回执失效 + ping 存活。**11/11 通过,两连稳定**。

## WT-P0-010 · P2 · 同素材缓存复用后,断线重连无法恢复待机画面

**根因(两个叠加)**:

1. `stopAll` 隐藏视频并显示断线占位后,重连的 `setIdle` 走同 URL 缓存复用分支**直接返回**,不恢复显示;正常续租与状态消息也无恢复入口 → 画面停在占位。
2. `ws-client` 的 `onerror` 在 CONNECTING 状态调用 `socket.close()` 会**吞掉浏览器的 close 事件** → 重连链死亡(实测探针 `reconnects:0, lastError:"socket-error"`,升级请求合法到达服务端但页面永远不再尝试)。这是审核复现步骤("仅关闭业务 WS 连接")能稳定卡死重连的直接机制。

**修复方式**:

- `src/web/overlay/player.ts`:`setIdle` 缓存复用分支按**占位可见性**恢复——占位可见(断线/初始)时恢复缓存片段的显示与循环播放;占位隐藏(表演进行中)不动,保留 WT-P0-009 的"迟到待机不覆盖动作"约束。
- `src/web/shared/ws-client.ts`:重连链加固——`onerror` 仅记录诊断不再主动 `close()`(连接失败由浏览器派发 error+close);增加 10 秒 CONNECTING 悬挂守卫与会话代数判定,防双循环;状态回调异常被捕获并计入探针,重连链永不中断。新增页面诊断探针 `window.__wtWs`(状态/重连次数/最后错误,无敏感信息)。
- `src/server/app.ts` + `transport/ws/index.ts`:升级入口增加 info 级日志(`ws.upgrade` 含 pathname/origin/host,origin 脱敏)与连接建立日志(`ws.connection-open`),为重连类问题提供服务端观测。

**回归用例**:新增 `scripts/e2e-reconnect-idle.mjs` 两段式(Edge 由外部以独立 profile 与固定调试端口启动,跨命令存活):

- **stage1**:待机正常播放(缓存建立)→ 精确杀服务(tsx 命令行过滤,排除脚本自身)→ 断线占位出现 → 服务确认停止 → 占位保持(无误恢复)→ STAGE1-PASS,Edge 保留。
- **stage2**(外部重启服务):**无任何新互动** → 页面自动重连、认证、登记、取得租约 → 断言可见视频 `idle.webm / loop=true / 非暂停 / 无占位` 恢复 → 补一发互动正常播放并回待机 → STAGE2-PASS,清理 Edge。

**结果**:两段式完整运行 **STAGE1-PASS + STAGE2-PASS**(截图 `.tools/e2e-reconnect-idle.png`);`ws.upgrade` 日志证实重连升级合法到达且 `connection-open → authenticated → lease-granted` 全链路成功。
