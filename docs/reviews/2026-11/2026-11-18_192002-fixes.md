## WT-P1-004 · 断线接管早于旧租约截止

**修复一(`renderer-lease.ts`)**:`unregister()` 的安全期限由 `now + takeoverSafetyMs` 改为 `max(旧租约 expiresAt, now) + takeoverSafetyMs` —— 保留旧租约剩余生命。旧页本地截止看门狗(ttl+500)保证断线后发声不超过剩余租约+500ms(与 onclose 处理延迟无关),安全窗(800)覆盖该附加与余量,新端接管不早于旧租约截止,关闭事件延迟超过固定安全窗不再同播。

**修复二(停止确认提前解除)**:断线属于"未确认停声",但旧页重连成功必然意味着它已走过 disconnected → stopAll(ws-client 先派发 disconnected 再调度重连)。新增 `lastDisconnect` 记录断线租约;该端重连登记后补发 `lease-release(旧 leaseId)`,`releaseLease()` 识别为真实停止确认,提前清零安全期限——等待不再是死等的 ttl+safety。leaseId 全局唯一且只下发过持有端,仅凭其匹配;新租约授予时作废旧记录。

**页面配合(`overlay/main.ts`)**:disconnected 时若仍持有租约则记录 `pendingReleaseLeaseId`(stopAll 已执行);重连 `renderer-registered` 后先补发释放、再申请新租约(避免一次注定被拒的申请轮次);取得新租约后清遗留。

**等待建议直达页面(`transport/ws/index.ts`)**:lease 拒绝响应此前丢弃 `retryAfterMs`,现已带上;页面 `scheduleLeaseRequest` 以服务端期限(权威)+250ms 余量重试,不再盲退避。

**单测**(可控时钟,69 项中 2 项更新/新增):断线时剩余租约 15s → t=1_801(旧实现授予点)被拒且 retryAfterMs>14s → 16_700(截止+700)仍拒 → 16_801 授予;断线端 A2 重连补发释放后 B 立即接管,无关 leaseId 无效果。

**实测**(`e2e-disconnect-safety.mjs` 重写,真实 `terminate` 路径,**8/8**):断线后立即申请被拒且等待覆盖剩余生命(≥10s)→ 期限后授予;A2 断线 → 新端被拒 → A2 重连补发释放 → 新端立即接管;显式释放零等待。

## WT-P1-009 · 诊断脚本强制停止其他项目进程

`e2e-reconnect-trace.mjs` 与 `e2e-reconnect-idle.mjs` 的 killServer 弃用「全机 node.exe 命令行含 tsx」筛选,改为三重归属校验:监听**本脚本操作的测试端口**的进程(同端口仅一个监听者,其他项目的 tsx 服务不监听本端口,不可能被选中)且进程名为 node.exe 且命令行含 `server[\\/]main\.ts`(兼容正反斜杠;再排除端口撞车下的异种进程)。双栈监听取 `Select-Object -First 1`。

**双进程实测**:WhaleTalk 服务(监听 3210)与另一工作区 `_bypass-test` 的 `npx tsx watch` 常驻进程并存,执行新逻辑后:目标停止(health 000),旁路 3 个进程(npx-cli / tsx cli / 服务进程)全部存活。

## WT-P1-010 · 自愈重载失败中断恢复能力

**修复(`ws-client.ts`)**:自愈重载前先 `fetch(当前文档路径, no-store)` 探测——响应非 ok(5xx 等)或请求失败时不重载,保留原页与探针继续重试;文档恢复后下一轮自愈条件达成时再重载。服务真宕机时本就走快速 error 路径,不涉自愈。

**实测(新增 `e2e-selfheal-503.mjs`,CDP Fetch 拦截注入 503,3/3)**:握手悬挂与文档 503 并存时,自愈触发但**不重载**(65s 观察窗探针存活、无 `wtWsReloadAt`);解除注入后自动重载并恢复循环待机。

**`e2e-selfheal-verify.mjs` 退出码**:恢复失败返回非零;门槛为恢复能力,自愈路径是否走到作信息输出(Vite 全量重载可能抢先恢复,属更快路径,自愈路径由 503 场景在文档不可用时定向验证)。
