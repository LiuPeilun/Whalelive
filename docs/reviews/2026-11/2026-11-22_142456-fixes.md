## WT-P2-013 · P2 · 音频故障后,已开始的冷场仍可能被打断 — 已修复

- **开过口的事实按轨道历史保留**(`session.ts`):表演条目新增 `audioEverStarted` 标记——音频回执到达 `started` 即置位,此后轨道转为 `failed`/`ended` 也不丢;`opened()` 判定重写:
  1. `audioEverStarted` → **已开口**(音频 started 后播放出错不再回退为可打断);
  2. 音频**起播前 failed** → 已转无声播放,按**动画边界**(动画 started/ended 即已开口)——加载失败与起播被拒两条路径不再打断已展示字幕/动画的话题;
  3. 无声降级(无音频轨道)→ 按动画边界(上轮已修,回归保持);
  4. 音频 `pending`/`ready`(仍可起播)→ `false`,**保留让位行为**(审核复验表首行语义不变)。
- 与上轮口径的差异:`opened()` 不再对音频轨道做"严格等于 started"的瞬时判断——`failed`/`ended` 都不再覆盖"开过口"的历史事实。
- **故障路径回归**(真模块 3 例,`playback/index.test.ts`):起播前 failed + 动画 started → 已开口(修复前为 false);音频 started 后 failed → 恒为已开口(修复前回退 false);音频 pending + 动画 started → 保留让位(false)。上轮两条反例(音频 ended 保留事实/无声降级按动画)回归保持通过。
