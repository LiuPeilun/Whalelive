## 逐项修复

### WT-P0-001 · apiFetch 空 POST 带 JSON 头 → 400

- 修改:`src/web/shared/ws-client.ts` — `apiFetch` 仅在存在请求体时声明 `content-type: application/json`;authorization 头保留。
- 验证:新增 `scripts/control-e2e.mjs`(CDP 驱动无头 Edge 打开控制台,真实点击 暂停 / 恢复 / 紧急停止)。修复前该脚本会复现 400;当前结果:三按钮均生效(顶栏徽章按 `调度:已暂停 → 运行中 → 已暂停` 迁移),服务端 `state.paused` 同步。紧急停止后追点恢复,服务端 `paused=false`(同时避免影响后续端到端)。

### WT-P0-002 · 畸形 WS 消息导致未捕获异常

- 修改:`src/server/transport/auth.ts` — `verify` 增加非字符串/空凭据守卫;`src/server/transport/ws/index.ts` — `handleAuth` 改为运行时校验(`protocolVersion` 必须为数字、`role` 必须为 `control|playback`、`credential` 必须为非空字符串,违规分别返回 UNSUPPORTED / AUTH_REJECTED 并关闭);`handleMessage` 拆出 `handleMessageInner` 并加连接级 try/catch(单条消息异常只记录 `ws.message-handler-error`,不影响服务与其他连接);解析结果增加结构校验(非对象或缺 `kind` 记 `ws.message-invalid`,未认证连接直接关闭)。
- 验证:`scripts/ws-smoke.mjs` 新增两例 — 缺失凭据的 auth 得到受控拒绝(`AUTH_REJECTED`,非崩溃);认证后发送 JSON `null` 再发 ping,得到 pong(连接与服务存活)。两例均 PASS。

### WT-P0-003 · Vite 文件服务暴露访问凭据

- 修改:`vite.config.ts` — `server.fs.allow` 收窄为 `src/web`、`src/shared`、`node_modules`;`server.fs.deny` 增加 `data/**`、`.env.local`、`.env`。
- 验证:ws-smoke 新增三例 — `/@fs/<root>/data/access.json` → 403;`/@fs/.../src/shared/protocol.ts` → 200;`data/config/settings.json` → 403/404 均不可读(该文件从未保存时不存在,404 属正常,deny 机制由 access.json 的 403 证明)。控制台与 overlay 页面、共享模块导入、HMR 客户端加载经两个浏览器端到端确认正常。

### WT-P0-004 · 满载队列拒绝高优先级事件

- 修改:`src/server/modules/interaction/queue.ts` — 抽出 `evictableIndex()`(仅普通聊天可被挤出,选优先级最低、同优先级最旧);腾位条件改为 `item.priority >= victim.priority`,不再要求新事件是 chat。礼物 / 大航海 / 醒目留言 / 人工动作因此可进入满载的聊天队列;队内无聊天时依旧拒绝。
- 验证:`queue.test.ts` 新增两例 — 满载聊天队列接受 gift(60) 与 manual(100) 并以 `capacity-evict-chat` 记录挤出;满载且无聊天时礼物仍被 `queue-full` 拒绝。

### WT-P0-005 · 待机动画播放一轮后停止

- 修改:`src/web/overlay/video-track.ts` — `prepare(url, loop, indefinite=false)` 新增 indefinite 语义:true 时媒体元素自身 `loop=true`,时间轴"一轮即结束"判定与 `ended` 事件不再兑现(仅 stop/错误兑现);`src/web/overlay/player.ts` — `setIdle` 以 `indefinite=true` 准备待机片段。表演片段语义不变(P0 无语音,循环动作一轮即结束,与 ARCHITECTURE §7 在 P1 接入音频后对齐)。
- 验证:`scripts/browser-e2e.mjs` 新增 8 秒采样(16 × 500ms):`loop === true`、全程非暂停、观察到 currentTime 回绕(即完成至少一个完整周期)→ 通过;随后 dance 表演结束仍能回到持续循环的待机。

### WT-P0-006 · 紧急停止漏清已到期礼物

- 修改:`src/server/modules/interaction/gifts.ts` — `clear()` 同时清空 `ready` 待产出数组。
- 验证:`gifts.test.ts` 新增一例 — 跨窗口旧礼物进入待产出后 `clear()`,`sweep()` 两次(含新窗口到期)均返回空。

### WT-P0-007 · 租约失效后播放器继续执行

- 修改:`src/web/overlay/main.ts` — 新增 `armLeaseDeadline(ttlMs)`:成功取得/续期租约时以 `ttlMs + 1500ms` 建立本地截止看门狗;到期未续成功即认定播放权失效:清租约、停续租、本地停止当前播放(`player.stop`)、状态提示并重新申请租约。续租失败分支改为 `dropLeaseAndStopIfHeld()`:持有租约时停止播放,首次申请被拒仅重试。断线与页面卸载路径同步清理看门狗。
- 验证:代码路径检查 + 类型检查;双播放端竞争与到期停止的实际浏览器行为待 OBS 联调时复测(审核亦标注该项需浏览器复测)。

### WT-P0-008 · 降低容量后队列仍超过新上限

- 修改:`src/server/modules/interaction/queue.ts` — `setCapacity` 缩容时按"优先级最低、同优先级先挤普通聊天、再按最旧"淘汰至新上限,记录 `capacity-shrink`。
- 验证:`queue.test.ts` 新增一例 — 容量 2→1,保留 gift(80)、挤出 chat(40) 并记录原因。
