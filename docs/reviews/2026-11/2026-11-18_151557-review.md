# P1 第一批代码审核

固定回复、WAV 合成、HTTP 媒体读取与浏览器播放主链路已打通。现有模块边界适合继续接入服务提供方。第一批尚有 4 项 P1 和 3 项 P2，集中在失败恢复、禁止停止后发声、租约转交及播放结果准确性，包含一项已复现的 P0 动作回归。[实施记录](../../ROADMAP.md#L193)

## WT-P1-001 · P1 · 提供方拒绝会逃出调度并阻塞后续任务

生成与合成阶段用 `Promise.race` 处理超时，但拒绝会直接抛出。下一层只有播放阶段的 `.catch`，出队入口则以 `void dispatch(next)` 启动任务。隔离服务启动后临时让音频缓存目录不可用，发送两条模拟弹幕。第一条触发固定本地合成的 `ENOENT` 未处理拒绝，当前任务停在 `synthesizing`，第二条仍在排队。验证进程安装了拒绝观察器以便读取状态，默认 Node 配置下未处理拒绝还可能结束进程。[提供方调用](../../../src/server/modules/interaction/index.ts#L268) · [出队入口](../../../src/server/modules/interaction/index.ts#L368) · [本地合成写入](../../../src/server/integrations/tts/fixed-local.ts#L54)

应按任务版本处理生成失败与合成失败，分别走保底文本和无声降级，并在 `finally` 清理派生调用。用拒绝型提供方和真实缓存写入失败验证下一条仍能继续，旧任务的错误也不会清理新的当前任务。

## WT-P1-002 · P1 · 等待租约的音频可在紧急停止后才派发

等待循环只在进入迭代时检查 `signal.aborted`。用真实 playback 模块和可控时钟，让当前任务在等待租约，从等待宽限边界执行 `abort()` 与 `stop()`，并在下一次轮询前授予租约。已取消的任务仍然派发了携带音频的 `performance`。会话在取消之后才注册 `abort` 监听，收不到已经发生的中止事件。若此时仍无租约，也可能派发已取消任务的无声版本。[等待及派发](../../../src/server/modules/playback/index.ts#L101) · [播放会话中止监听](../../../src/server/modules/playback/session.ts#L103)

等待结束后和创建会话入口都应拒绝已中止任务。验收需覆盖在宽限边界停止，以及同一时刻有播放端拿到租约的交错顺序。

## WT-P1-003 · P1 · 旧音频加载完成会让紧急停止丢失当前发声对象

在真实 Edge 延迟表演 A 的 `canplaythrough` 回调，停止 A 并恢复排队。表演 B 已经开始播放未静音音频后，再放行 A 的加载回调。旧 `prepare()` 仍把 A 赋给音频轨道的 `current`。紧急停止 B 后，实际观测为服务端 `paused=true、current=null`，B 的媒体对象仍在播放且未静音。播放器在 `await` 后的版本检查已经晚于轨道内的指针写入。[音频加载归属](../../../src/web/overlay/audio-track.ts#L17) · [停止音频](../../../src/web/overlay/audio-track.ts#L52) · [播放器版本检查](../../../src/web/overlay/player.ts#L182)

音频轨道应持有当前加载的归属，停止时使在途加载失效，迟到回调不得替换后续表演的媒体对象。用同样的交错顺序验证 B 的实际元素被暂停或静音。

## WT-P1-004 · P1 · 租约转交把停止消息发给新端，造成两页同时播放

会话调用 `sendStop` 时只给出表演 ID。实现按调用时的 `primaryTarget()` 选择目标。旧租约被回收或新端先取得租约后，目标可能已经变为 B。模块定向验证中，A 收到表演，B 收到 A 的 `stop`，随后 B 又收到自己的带音频表演。

真实双页面验证将租约时长设为 3000 毫秒、续期间隔设为 1000 毫秒，保持 A 的 WS 打开但抑制续租，提前排入第二项。B 取得租约并开始播放时，A 未收到对应 stop，两页的音频元素均为播放中且未静音。旧端本地截止使用 `ttlMs + 1500`，期间存在旧音频未停而新端已出声的窗口。[停止目标](../../../src/server/modules/playback/index.ts#L94) · [接管路径](../../../src/server/modules/playback/index.ts#L132) · [会话失去租约](../../../src/server/modules/playback/session.ts#L196) · [页面截止时间](../../../src/web/overlay/main.ts#L129)

应把停止消息绑定到实际派发端，并让新端发声满足现有契约的旧端停止确认或安全过期条件。验收需同时观察两页的实际播放状态和旧表演终态。[租约契约](../../ARCHITECTURE.md#L230)

## WT-P1-005 · P2 · 先打开普通预览会拿走 OBS 音频播放权

每个 `/overlay` 页面在登记成功后都会申请播放租约，发声只检查派发里的租约 ID。使用实际默认链接先打开普通 Edge 预览，再打开同 URL 的第二个页面作为 OBS 入口的浏览器替身。预览持有租约并播放未静音音频，第二页没有收到表演。首次取得租约由打开顺序决定，现有实现无法达到普通预览默认静音、OBS 负责可听播放的要求。[自动申请租约](../../../src/web/overlay/main.ts#L159) · [页面发声判断](../../../src/web/overlay/player.ts#L122) · [P1 验收](../../ROADMAP.md#L83)

应通过既有播放入口明确申请音频归属的用途。验收时先打开普通预览，再启动 OBS 浏览器源，确认预览静音且 OBS 收到表演。

## WT-P1-006 · P2 · 音频起播失败仍被回报为完整播放成功

在真实 Edge 让音频元素 `play()` 返回 `NotAllowedError`，保留正常 WAV 预加载和视频路径。页面没有播放声音，但音频回执依次是 `ready`、`started`、`ended`。轨道把 `play()` 拒绝及播放期 `error` 都解析为完成，播放器在起播确认前发出 `started`，随后立即回待机，字幕降级也未生效。[音频轨道失败处理](../../../src/web/overlay/audio-track.ts#L38) · [页面回执](../../../src/web/overlay/player.ts#L240)

区分已起播、自然结束、播放失败和取消。起播被拒需报告稳定错误，保留无声动作与字幕的合理展示时间，再继续队列。

## WT-P1-007 · P2 · 给确定性动作加音频后，跳舞提前结束

所有携带音频的动作都以持续循环加载，音频先结束时统一停止动画。实际 Edge 中，模拟弹幕「大肥鱼跳舞」触发本地素材 `dance.webm`。素材全长 10.042 秒，动画在约 3.73 秒时被暂停，`ended=false`、`loop=true`，页面已回到待机。P0 的一次性动作因此会随一句简短确认音频被截断。[启用循环](../../../src/web/overlay/player.ts#L187) · [音频结束后停止动作](../../../src/web/overlay/player.ts#L245) · [说话动画约定](../../ARCHITECTURE.md#L171)

应区分随语音结束的说话循环与一次性确定动作。复测 `talk` 跟随语音结束，并确保 `dance` 在简短确认音频先结束时能完成一次动作。
