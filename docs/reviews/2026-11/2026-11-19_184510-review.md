# P1 第三批 DeepSeek 接入首次审查

结论为需修改，共 4 项 P2。模型接入沿用既有回复与播放边界。本地假端点经模拟弹幕、音频、动作和播放回执完成闭环，未知动作被回退。预览错误、阶段统计、模型设置和离线验证仍有可复现问题。实际比较为 3 个提交、26 个文件。[P1 验收](../../ROADMAP.md#L69)

## WT-P1-021 · P2 · 预览吞掉上游故障，控制台无法判断模型是否可用

预览与直播共用回复路由。路由捕获 DeepSeek 的异常后立即返回带 `fixed-local` 标签的正常回复，HTTP 层的 `LLM_UNAVAILABLE` 和 `LLM_TIMEOUT` 无法处理这些异常。选择 DeepSeek 但缺少 Key 同样进入固定回复，与主动选择固定回复使用相同标签。[错误回退](../../../src/server/integrations/llm/reply-router.ts#L22) · [预览入口](../../../src/server/transport/http/index.ts#L211) · [错误映射](../../../src/server/transport/http/index.ts#L63)

通过真实 HTTP 预览调用假端点。上游返回 401 时，配置显示生效来源为 DeepSeek，预览返回 HTTP 200 和 `fixed-local`，响应没有错误码。上游一直挂起时，约 8020 毫秒后连接按期取消，预览仍返回 HTTP 200 和 `fixed-local`。操作者无法区分无效密钥、超时和主动选择固定回复。

保留直播的自动降级，给预览提供可诊断的结果，并让设置了 DeepSeek 的回退与主动选择固定回复可区分。使用上游拒绝、挂起、非法回复与缺失 Key 的场景复验，确认控制台能够显示对应原因。

## WT-P1-022 · P2 · 生成耗时被重复计入排队，部分终态漏记用量

排队耗时从入队算到模型完成，规则回复则算到语音完成。模型时长因此同时计入排队与生成；规则回复即使完成语音合成，合成耗时仍是空。一次实测展示排队 455 毫秒、生成 278 毫秒、合成 25 毫秒和播放阶段 1240 毫秒，总计却为 1720 毫秒。另一条有音频的跳舞指令显示合成为空。[阶段差值](../../../src/server/modules/interaction/index.ts#L133) · [模型结束和合成](../../../src/server/modules/interaction/index.ts#L349)

用量只在播放结算时增加。假端点已返回 32 token，随后在等待播放时按紧急停止，最近一条统计和累计 token 都保持原值。另一次假端点返回非法文本及 32 token，格式检查抛错并正常降级，但上游已提供的用量丢失。对照样例的累计值始终停在前一条的 32 token。[用量写入](../../../src/server/modules/interaction/index.ts#L409) · [紧急停止](../../../src/server/modules/interaction/index.ts#L475) · [上游用量解析](../../../src/server/integrations/llm/deepseek.ts#L125)

按出队、实际开始合成和各阶段终点分别计时。将已经取得的模型用量与播放终态解耦，按请求归属只累计一次。覆盖规则语音、无播放端失败、模型响应后停止及非法输出仍上报用量，继续保留迟到结果不得播放的约束。

## WT-P1-023 · P2 · 默认模型、思考开关及截断状态未按 DeepSeek 契约处理

架构与示例配置采用 `deepseek-flash`，并要求显式发出 `thinking: { type: 'disabled' }`。实测只配置 Key 和本地端点、不设模型时，实际发送 `deepseek-chat`。控制台显示思考已关，但出站请求完全没有 `thinking` 字段，实际模式取决于上游默认值。回复验证也只查看文本。假端点返回 `finish_reason: 'length'` 且内容含可解析 JSON 时，系统仍把它作为成功模型回复返回。只校验 JSON 形状会漏过上游明确报告的截断。[项目请求约定](../../ARCHITECTURE.md#L151) · [模型默认值](../../../src/server/app.ts#L85) · [请求构造](../../../src/server/integrations/llm/deepseek.ts#L99) · [响应校验](../../../src/server/integrations/llm/deepseek.ts#L123)

让代码默认值和出站思考模式与项目约定一致。识别上游明确标记的截断并走回退，同时保留对自定义兼容端点的预期兼容性。复验应检查实际出站请求与带完整 JSON 的 `length` 响应。

## WT-P1-024 · P2 · 标称离线的端到端检查仍调用在线 Edge TTS

零配置脚本仅清空模型 Key。服务继续使用默认 `edge-tts`，后续模拟弹幕走语音合成。用替身让 Edge TTS 握手一直等待，捕获到一次真实适配器入口调用。默认合成超时约 10 秒，脚本对统计的轮询先耗尽，三项统计断言失败，脚本退出 1。直接运行在当前环境可通过，仍会受外部语音服务时延影响。[零配置启动](../../../scripts/e2e-llm.mjs#L27) · [统计轮询](../../../scripts/e2e-llm.mjs#L63) · [默认语音提供方](../../../config/defaults.json#L25)

为测试实例预置 `fixed-local` 语音，保留零模型 Key 的场景，以及配置假 Key 的本地端点。复验时禁止或替换外部语音调用，脚本应仍然完成相同断言。
