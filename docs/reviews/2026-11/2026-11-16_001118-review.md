## WT-P0-007 · P2 · 租约回收后自动派发下一任务，回执租约不匹配

主要位置在 [派发目标和租约选择](D:/Project/dsh-workspace/WhaleTalk/src/server/modules/playback/index.ts:60)，相关位置为 [播放页回执构造](D:/Project/dsh-workspace/WhaleTalk/src/web/overlay/main.ts:52) 和 [本地租约截止处理](D:/Project/dsh-workspace/WhaleTalk/src/web/overlay/main.ts:87)。

### 复现与证据

1. 隔离配置使用合法的租约参数，ttlMs 为 3000，renewIntervalMs 为 1000。
2. Edge 播放页取得租约并播放 dance。仅拦截 lease-renew，保持业务 WS 开启。
3. dance 进行中排入 wave，等待服务端回收租约。
4. dance 立即结算为 failed / LEASE_LOST，interaction 自动调度 wave。
5. registry 此时没有租约，primaryTarget 仍返回已登记的播放端，wave 携带 leaseId 为 null 被派发。
6. 页面仍持有尚未到本地截止时间的旧租约，wave 的 ready 和 started 被服务端判为 stale-lease。随后本地截止处理会停止 wave 并重新申请租约，wave 的服务端会话仍在等待。

真实 Edge 日志记录了同一次连续调度。

```text
dance session-settled failed LEASE_LOST
wave dispatched leaseId=null
wave ready stale-lease
wave started stale-lease
```

约 5 秒后的实际快照如下，浏览器已经重新取得播放权并回到 idle，wave 仍未完成。

```json
{
  "current": {"action": "wave", "stage": "waiting-playback"},
  "playback": {"status": "dispatching"},
  "leaseReacquired": true,
  "video": {"source": "idle.webm", "loop": true, "paused": false}
}
```

另直接调用实际 playback 模块复现相同时序，使用合法的 1000 毫秒预加载超时以缩短验证。旧租约下的 ready / started、重新取租约后的 ended 均返回 stale，wave 最终返回 failed / PLAYBACK_TIMEOUT。浏览器用例保留默认 8000 毫秒预加载超时，在约 5 秒处采样后结束，未等待该浏览器会话的超时终态。

### 影响与修复方向

旧任务等待 120 秒的问题已经消除，因此本轮将优先级调整为 P2。异常恢复期间已排队的下一条互动仍会被中断并超时丢失，默认设置下还会额外等待预加载看门狗。

在现有播放模块内协调有效租约与派发时序，并保证页面回执绑定实际表演的派发身份。验收应在当前动作租约失效之前排入下一项，观察自动推进、重新取得播放权及下一项的成功终态。

当前 index.test.ts 和 lease-lost-e2e.mjs 都先重新取得租约，再提交下一项，跳过了实际 interaction 自动推进的空窗。补充用例需覆盖这个顺序。

## WT-P0-010 · P2 · 同素材缓存复用后，断线重连无法恢复待机画面

主要位置在 [setIdle 缓存复用分支](D:/Project/dsh-workspace/WhaleTalk/src/web/overlay/player.ts:100)，相关位置为 [断线停止处理](D:/Project/dsh-workspace/WhaleTalk/src/web/overlay/player.ts:182) 和 [重新登记后的 setIdle 调用](D:/Project/dsh-workspace/WhaleTalk/src/web/overlay/main.ts:131)。

### 复现与证据

1. 打开 overlay，等待 idle 正常播放，确保待机资源已经缓存。
2. 仅关闭该页业务 /ws 连接，保留页面和 HMR 连接。
3. 客户端自动重连，重新认证、登记并取得租约。
4. 在没有新互动的情况下观察画面。

真实 Edge 在断线后约 3.5 秒捕获如下状态。

```json
{
  "page": {
    "video": null,
    "placeholder": "flex",
    "label": "连接断开,等待重连…",
    "businessWebSocket": "OPEN"
  },
  "server": {
    "rendererCount": 1,
    "leaseHeld": true,
    "current": null,
    "playbackStatus": "idle"
  }
}
```

此处 video 为 null 表示找不到可见的视频元素。再次提交 wave 后可以正常播放，wave 结束才恢复可见的循环 idle。

### 原因与修复方向

stopAll 隐藏视频并显示断线占位，但保留 idleDescriptor 与已完成的 idleClipPromise。重连登记再次调用 setIdle 时，同 URL 分支复用缓存并直接结束，没有恢复片段显示与播放。正常续租和状态消息也不会调用恢复逻辑，所以无新互动时画面持续停在占位提示。

复用缓存时仍需在重连后的待机状态恢复画面，同时保留 WT-P0-009 的迟到待机不能覆盖正在执行动作的约束。增加同 URL、已完成缓存、断线并自动重连且没有新互动的回归用例。
