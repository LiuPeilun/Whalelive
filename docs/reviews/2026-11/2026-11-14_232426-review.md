## WT-P0-007 · P1 · 租约失效后旧会话未结束，后续任务被阻塞

位置在 [本地租约截止处理](D:/Project/dsh-workspace/WhaleTalk/src/web/overlay/main.ts:89)、[播放器停止](D:/Project/dsh-workspace/WhaleTalk/src/web/overlay/player.ts:148) 和 [服务端租约扫描](D:/Project/dsh-workspace/WhaleTalk/src/server/modules/playback/index.ts:147)。

### 复现

1. 在隔离测试配置中将租约时长设为 3000 毫秒、续租间隔设为 1000 毫秒，均处于现有设置允许范围。
2. 保持业务 WebSocket 开启，只拦截页面发出的 lease-renew 消息。
3. 派发 dance，再排入 wave。
4. 本地看门狗停止表演，页面回到 idle 并重新取得租约。
5. 服务端原任务仍为 waiting-playback，wave 继续排队。

真实 Edge 观察结果如下。

```json
{
  "sameTaskStillWaiting": true,
  "currentStage": "waiting-playback",
  "queueLength": 1,
  "video": {"source": "idle.webm", "loop": true, "paused": false},
  "leaseReacquired": true
}
```

### 原因与影响

客户端清空 leaseId 并调用 player.stop，取消了后续轨道处理，却没有完成服务端对应表演的终态。服务端 tick 回收租约时只更新 registry，播放会话继续等待。

该表演已经开始，预加载看门狗无法释放它，剩余恢复依赖整体看门狗。默认整体超时为 120000 毫秒，期间后续礼物和人工动作均无法继续调度。

原问题中缺少本地停止的部分已经修复。本轮确认了实际队列阻塞影响，因此将本项优先级调整为 P1。

### 修复与验收方向

将租约失效与该租约所属表演的终态关联，及时结束服务端等待并通知 interaction，同时保留实际 runId、leaseId、performanceId 和派发所有权校验。

增加覆盖本地停止、服务端结算及重新调度的联动用例，验证重新取得播放权后下一项可执行，旧回执保持失效。

## WT-P0-009 · P2 · 待机尚未加载时派发动作，结束后无法恢复正确待机

位置在 [缓冲位选择](D:/Project/dsh-workspace/WhaleTalk/src/web/overlay/video-track.ts:27)、[待机片段缓存](D:/Project/dsh-workspace/WhaleTalk/src/web/overlay/player.ts:60) 和 [回到待机](D:/Project/dsh-workspace/WhaleTalk/src/web/overlay/player.ts:43)。

### 复现

1. 新打开 overlay，暂停首个 idle.webm 请求，使待机处于预加载状态。
2. 播放端登记后立即派发 dance。
3. 两次 prepare 都在 activeSlot 为 -1 时运行，选中同一个 video 元素，动作地址覆盖待机地址。
4. 两个准备过程都随动作加载完成。
5. 服务端收到正常 ended 并回到空闲，页面随后再次播放 dance。

真实 Edge 在表演完成后捕获的状态如下。

```json
{
  "afterCompletedPerformance": {"source": "dance.webm", "loop": false, "paused": false},
  "serverCurrent": null
}
```

### 原因与影响

缓冲位只按已显示的 activeSlot 选择，预加载中的占用没有登记。idleClipPromise 缓存共享 DOM 元素上的片段，该元素的 src 被覆盖后仍被作为待机使用。

该情况可发生于播放页刚打开或刷新、待机加载较慢而已有互动待播时。内存媒体元素替身和真实 Edge 均已复现。正常起播后的持续循环已经修复，本项针对加载与派发交错时的资源恢复。

### 修复与验收方向

管理预加载中的缓冲位和片段归属，确保异步完成与缓存引用对应同一资源，回到待机时资源和循环配置正确。

增加延迟 idle 后立即派发动作的用例，验证动作结束后显示 idle.webm、持续循环，并正常处理下一次动作。
